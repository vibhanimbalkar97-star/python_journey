# **Pydantic vs Plain Python**

**Plain Python** uses normal variables, dictionaries and classes.

**Pydantic** validates data and checks whether it matches the expected types and rules.

## **1. Plain Python example**

```
student = {    "name": "Vibha",    "age": "25"}print(student)
```

Output:

```
{'name': 'Vibha', 'age': '25'}
```

Here, age is a string, even though we may expect an integer. Plain Python dictionaries don't automatically validate the data.

## **2. Pydantic example**

```
from pydantic import BaseModelclass Student(BaseModel):    name: str    age: intstudent = Student(name="Vibha", age="25")print(student)
```

Output:

```
name='Vibha' age=25
```

Pydantic converts the valid string `"25"` into integer `25`.

If you provide invalid data, such as `"twenty"`, Pydantic raises a validation error.

## **3. Main differences**

| Plain Python                                  | Pydantic                   |
| --------------------------------------------- | -------------------------- |
| Normal variables and classes                  | Data validation library    |
| No automatic dictionary validation            | Automatic model validation |
| No automatic type conversion for dictionaries | Supports type conversion   |
| Manual validation needed                      | Built-in validation        |
| Used for general programming                  | Commonly used in FastAPI   |

## **4. Why use Pydantic in FastAPI?**

Example:

```
from fastapi import FastAPIfrom pydantic import BaseModelapp = FastAPI()class Student(BaseModel):    name: str    age: int@app.post("/students")def create_student(student: Student):    return student
```

When a user sends JSON:

```
{
    "name": "Vibha",
    "age": 25
}
```

FastAPI uses Pydantic to validate the incoming JSON data.

**Remember for interviews:**

- Plain Python = Write program logic.
- Pydantic = Validate and structure data.
- FastAPI + Pydantic = Validate API request and response data.

**Simple trick:** Pydantic acts like a security checker for your API data.
