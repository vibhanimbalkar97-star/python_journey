# **PUT Request in FastAPI – Beginner Explanation**

## **1. What is PUT?**

**PUT = Update an existing record.**

Example: A student already exists with ID `S001`.

Old data:

```
{
    "name": "Rahul",
    "age": 22,
    "course": "Python",
    "marks": 80
}
```

Now Rahul wants to update his age and marks.

The frontend sends the updated student data using a PUT request.

## **2. How does PUT work? (Client to Backend flow)**

**1. React Frontend**

User edits student form

PUT request + student ID + updated data

**2. FastAPI**

Receives request

**3. Pydantic**

Validates updated data

**4. Find student**

Search using student ID

**5. Update database**

Replace existing data

200 OK

**6. Send updated data to React**

## **3. What does the PUT function accept?**

Example:

```
@app.put("/students/{student_id}")def update_student(student_id: str, student: Student):    ...
```

There are two important parameters:

| Parameter          | Comes from   | Meaning                 |
| ------------------ | ------------ | ----------------------- |
| `student_id: str`  | URL path     | Which student to update |
| `student: Student` | Request body | New student data        |

Let's understand each one.

**A.&#x20;**`student_id: str`

```
@app.put("/students/{student_id}")
```

URL:

```
/students/S001
```

Here `S001` comes from the URL.

FastAPI automatically passes it into `student_id`.

**B.&#x20;**`student: Student`

```
student: Student
```

This is the request body.

Frontend sends:

```
{
    "name": "Rahul Sharma",
    "age": 23,
    "course": "FastAPI",
    "marks": 95
}
```

FastAPI validates it using the Student Pydantic model.

## **4. Complete PUT logic (simple example)**

Let's use a Python list as temporary storage.

**Step 1: Create model and existing data**

```
from fastapi import FastAPI, HTTPExceptionfrom pydantic import BaseModelapp = FastAPI()class Student(BaseModel):    name: str    age: int    course: str    marks: intstudents = [    {        "id": "S001",        "name": "Rahul",        "age": 22,        "course": "Python",        "marks": 80    },    {        "id": "S002",        "name": "Priya",        "age": 21,        "course": "React",        "marks": 90    }]
```

**Step 2: Create PUT API**

```
@app.put("/students/{student_id}")def update_student(student_id: str, student: Student):    for item in students:        if item["id"] == student_id:            item.update(student.model_dump())            return {                "message": "Student updated successfully",                "student": item            }    raise HTTPException(        status_code=404,        detail="Student not found"    )
```

## **5. Understand the logic step by step**

Suppose frontend sends:

URL:

```
PUT /students/S001
```

Body:

```
{
    "name": "Rahul Sharma",
    "age": 23,
    "course": "FastAPI",
    "marks": 95
}
```

What happens?

1. `student_id` receives `"S001"` from URL.
2. `student` receives the JSON body as a Pydantic object.
3. Pydantic validates the incoming data.
4. `for item in students` checks each existing student.
5. `if item["id"] == student_id` finds the matching student.
6. `student.model_dump()` converts the new data into a dictionary.
7. `item.update()` replaces the old values with new values.
8. `return` sends the updated student to React.

**Important:**

```
item.update(student.model_dump())
```

This updates the existing dictionary. It doesn't create another student.

The ID remains unchanged because we didn't include `id` in the request body.

## **6. What if student ID doesn't exist?**

Suppose the frontend sends:

```
PUT /students/S999
```

No matching student is found.

FastAPI returns:

```
{
    "detail": "Student not found"
}
```

Status code: `404 Not Found`.

## **8. Important difference: POST vs PUT vs PATCH**

| Method | Purpose                        | Example                |
| ------ | ------------------------------ | ---------------------- |
| POST   | Create new record              | Add student            |
| PUT    | Replace/update complete record | Update student details |
| PATCH  | Update selected fields         | Update only marks      |

**PUT rule:** In this example, all fields in the `Student` model are required. PUT generally represents a full replacement of the resource. If you want to update only one or two fields, use PATCH with optional fields.

## **Quick revision**

```
@app.put("/students/{student_id}")def update_student(student_id: str, student: Student):
```

- `@app.put` → Defines update API.
- `student_id` → Which record?
- `student: Student` → What new data?
- `for` → Search existing records.
- `if` → Find matching ID.
- `model_dump()` → Convert new data to dictionary.
- `update()` → Replace old field values.
- `HTTPException(404)` → Record not found.

**Remember this logic:**

`Client sends ID + updated body → FastAPI receives → Pydantic validates → Find existing record → Update → Return response.`




यह code **PUT API से existing student का data update** करने के लिए है। इसमें student की सभी fields देना जरूरी नहीं है, क्योंकि हमने `None` allow किया है।

चलो step-by-step समझते हैं।

### **1. StudentUpdate Model**

```
class StudentUpdate(BaseModel):    name: str | None = Field(None, min_length=2, max_length=50)    age: int | None = Field(None, gt=0, lt=100)    course: str | None = Field(None, max_length=50)    marks: str | None = Field(None, gt=0, le=100)    email: EmailStr | None = None
```

**इसका मतलब:** Client जितनी fields update करना चाहता है, उतनी ही भेज सकता है।

- `str | None` → value string हो सकती है या `None`।
- `Field(None)` → default value `None` है।
- `min_length=2` → कम से कम 2 characters।
- `max_length=50` → ज्यादा से ज्यादा 50 characters।
- `gt=0` → 0 से ज्यादा।
- `lt=100` → 100 से कम।
- `le=100` → 100 या उससे कम।
- `EmailStr` → email format validate करता है।

**ध्यान दो:** `marks` का type `str` नहीं, `int` या `float` होना चाहिए, क्योंकि marks number हैं।

### **2. PUT API और function parameters**

```
@app.put("/student/{student_id}")def update_student(    student_update: StudentUpdate,    student_id: str = Path(...)):
```

यहाँ दो values client से आती हैं:

| Parameter        | Data कहाँ से आता है? |
| ---------------- | -------------------- |
| `student_update` | Request body (JSON)  |
| `student_id`     | URL path             |

उदाहरण:

URL:

```
PUT /student/S001
```

Request Body:

```
{
    "name": "Rahul Sharma",
    "age": 23
}
```

यहाँ `S001` URL से आएगा और `name`, `age` JSON body से आएंगे।

### **3. Existing data load करना**

```
data = load_data()
```

इसका मतलब: JSON file या जहाँ भी data save है, वहाँ से existing students का data लाओ।

उदाहरण:

```
data = {    "S001": {        "name": "Rahul",        "age": 22,        "course": "Python"    }}
```

### **4. Student ID check करना**

```
if student_id not in data:    raise HTTPException(        status_code=400,        detail="Student not found"    )
```

अगर `S001` data में नहीं मिला, तो error भेजेगा।

### **5. Existing student निकालना**

```
existing = data[student_id]
```

इसका मतलब `S001` की existing information निकालना।

```
existing = {    "name": "Rahul",    "age": 22,    "course": "Python"}
```

### **6. New data को dictionary में convert करना**

```
update = student_update.model_dump()
```

Pydantic object को dictionary में convert करता है।

उदाहरण:

```
update = {    "name": "Rahul Sharma",    "age": 23,    "course": None,    "marks": None,    "email": None}
```

### **7. Loop से data update करना**

```
for key, value in update.items():    existing[key] = value
```

यहाँ:

- `key` → field का नाम, जैसे `name`
- `value` → उसकी नई value, जैसे `Rahul Sharma`
- `existing[key]` → existing dictionary में उस field की value बदलना।

**लेकिन यहाँ एक जरूरी सुधार है:** `None` वाली fields भी पुराने data को `None` कर देंगी। इसलिए यह लिखो:

```
update = student_update.model_dump(exclude_unset=True)for key, value in update.items():    if value is not None:        existing[key] = value
```

अब केवल client द्वारा भेजी गई non-None values update होंगी।

### **8. Student model बनाना**

```
student = Student(id=student_id, **existing)
```

इसका मतलब:

- `id=student_id` → student की ID देना।
- `**existing` → dictionary की सभी key-value pairs को अलग-अलग arguments की तरह भेजना।

उदाहरण:

```
Student(    id="S001",    name="Rahul Sharma",    age=23,    course="Python")
```

### **9. Updated data save करना**

```
data[student_id] = student.model_dump(exclude={"id", "grade"})save_data(data)
```

- `model_dump()` → Student object को dictionary में बदलता है।
- `exclude={"id", "grade"}` → dictionary में ID और grade शामिल नहीं होंगे।
- `save_data(data)` → updated data को file में save करता है।

### **10. Response भेजना**

```
return {    "message": "Student updated successfully",    "student": student}
```

Client को success message और updated student की details मिलेंगी।

### **पूरा flow याद रखो**

**React / Client**

PUT request + student_id + JSON body

**FastAPI + Pydantic validation**

**Existing student check**

**Update fields + Save data**

**Updated response to client**

**एक जरूरी बात:** तुम्हारा code partial update कर रहा है, इसलिए REST API convention के हिसाब से इसके लिए `PATCH` ज्यादा सही है। `PUT` सामान्यतः पूरे resource को replace करने के लिए होता है।
