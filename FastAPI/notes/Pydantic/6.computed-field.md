## **Computed Field in Pydantic**

A **computed field** is a field whose value is calculated automatically using other fields in a model.

### **1. When and why do we use it?**

Use `@computed_field` when you want to calculate a value from existing fields instead of asking the user to provide it.

**Example:** Calculate a student's total marks from three subjects.

### **2. Code example**

```
from pydantic import BaseModel, computed_fieldclass Student(BaseModel):    name: str    maths: int    science: int    english: int    @computed_field    @property    def total_marks(self) -> int:        return self.maths + self.science + self.englishstudent = Student(    name="Rahul",    maths=80,    science=90,    english=85)print(student.total_marks)print(student.model_dump())
```

**Output:**

```
255{    'name': 'Rahul',    'maths': 80,    'science': 90,    'english': 85,    'total_marks': 255}
```

### **3. Where do we use it?**

- In Pydantic models.
- In FastAPI response models.
- When a value depends on other model fields.

### **4. What if we don't use it?**

You can calculate the value manually:

```
total = student.maths + student.science + student.english
```

This works, but you must calculate it separately whenever needed.

### **5. Important difference**

| Normal field        | Computed field                         |
| ------------------- | -------------------------------------- |
| User provides value | Python calculates value                |
| `maths: int`        | `total_marks`                          |
| Stores input data   | Calculates from other fields           |
| No decorator needed | Uses `@computed_field` and `@property` |

**Remember:** `@computed_field` is useful when you want calculated values to appear in Pydantic's serialized output (`model_dump()`).

It does not automatically validate or store a separate database value.

### **Why do we use&#x20;**`@property`**?**

`@property` allows us to use a method like a normal variable (attribute), without calling it using `()`.

**1. Without&#x20;**`@property`

```
class Student:    
def total(self):        
return 80 + 90 + 85
s = Student()
print(s.total())
```

Output:

```
255
```

Notice: We need `()` to call the method.

**2. With;**`@property`

```
class Student:    
@property    
def total(self):        
return 80 + 90 + 85
s = Student()
print(s.total)
```

Output:

```
255
```

Notice: No `()` needed. It behaves like an attribute.

### **What if we don't use&#x20;**`@property`**&#x20;with&#x20;**`@computed_field`**?**

```
from pydantic import BaseModel, computed_fieldclass Student(BaseModel):    maths: int    science: int    @computed_field    def total(self) -> int:        return self.maths + self.science
```

This is **not the correct usage**. Pydantic's `@computed_field` expects a property or cached property.

Correct:

```
@computed_field@propertydef total(self) -> int:    return self.maths + self.science
```

### **Remember**

- `@property` → access a method like an attribute.
- `@computed_field` → include that calculated property in Pydantic serialization, such as `model_dump()`.

**Simple trick:** `@property` makes a method look like a field; `@computed_field` makes that property part of Pydantic's output.







Good question! The confusion is between `@computed_field` and `@property`. They have different jobs.

### **1. Why can you access&#x20;**`s.check_grade`**&#x20;without&#x20;**`()`**?**

Because you used `@property`.

```
@propertydef check_grade(self):    return "A+"
```

`@property` converts a method into an attribute.

So:

```
s.check_grade     # A+
```

Instead of:

```
s.check_grade()   # Not needed
```

### **2. What happens if you remove&#x20;**`@property`**?**

```
@computed_fielddef check_grade(self) -> str:    return "A+"
```

This is not the correct usage of Pydantic's `@computed_field`. It expects a property or cached property.

Without `@computed_field` and `@property`:

```
def check_grade(self):    return "A+"print(s.check_grade())
```

Now you must use `()` because it is a normal method.

### **3. Difference between both decorators**

| Decorator         | Purpose                                           |
| ----------------- | ------------------------------------------------- |
| `@property`       | Access a method like an attribute without `()`    |
| `@computed_field` | Include the calculated property in `model_dump()` |

### **4. Understand with your grade example**

```
@computed_field@propertydef check_grade(self) -> str:    if self.marks >= 90:        return "A+"    elif self.marks >= 80:        return "A"    else:        return "F"
```

```
print(s.check_grade)print(s.model_dump())
```

Output:

```
A+
```

Your dictionary will also contain:

```
'check_grade': 'A+'
```

### **5. What if you use only&#x20;**`@property`**?**

```
@propertydef check_grade(self):    return "A+"
```

You can still do:

```
print(s.check_grade)  # A+
```

But `check_grade` will **not automatically appear in&#x20;**`model_dump()`.

**Easy trick to remember:**

- `@property` = How to access the calculated value.
- `@computed_field` = Include that value in Pydantic's serialized output.

You use both together when you want calculated values to be accessible like attributes and included in API/dictionary output.
