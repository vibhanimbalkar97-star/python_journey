# **POST Request in FastAPI – Complete Beginner Notes**

## **1. What is a POST request?**

**POST = Send data to the backend to create something new.**

Example:

- Register a new user.
- Add a student.
- Create a product.
- Submit an order.
- Save a new AI chat conversation.

Suppose a user fills a student form in React. POST sends that student's data to FastAPI.

## **2. How does POST work? (Flow)**

**1. React Frontend**

User fills student form

Axios POST request + JSON body

**2. FastAPI**

Receives request

**3. Pydantic**

Validates request data

**4. Python Function**

Business logic, duplicate checking

**5. Database**

Save new record

Response

201 Created

**6. React receives success response**

## **3. Basic POST API – Step by step**

**Step 1: Import**

```
from fastapi import FastAPIfrom pydantic import BaseModel, Fieldapp = FastAPI()
```

**Step 2: Create Pydantic model**

```
class Student(BaseModel):    id: str    name: str = Field(min_length=2)    age: int = Field(gt=0)    course: str    marks: int = Field(ge=0, le=100)
```

**Step 3: Create a POST endpoint**

```
students = []@app.post("/students", status_code=201)def create_student(student: Student):    data = student.model_dump()    students.append(data)    return {        "message": "Student created successfully",        "student": data    }
```

## **5. How to handle errors?**

There are different types of errors in POST requests.

### **A. Missing or invalid fields**

Example: User sends age as `"hello"` instead of an integer.

```
{
    "id": "S001",
    "name": "Rahul",
    "age": "hello",
    "course": "Python",
    "marks": 90
}
```

FastAPI automatically handles Pydantic validation errors.

422 Unprocessable Entity

You don't need to write `try-except` for normal request-body validation.

### **B. Duplicate records**

Suppose student ID `S001` already exists.

If another user sends `S001`, you should not save it again.

```
from fastapi import HTTPExceptionstudents = []@app.post("/students", status_code=201)def create_student(student: Student):    for existing in students:        if existing["id"] == student.id:            raise HTTPException(                status_code=409,                detail="Student ID already exists"            )    data = student.model_dump()    students.append(data)    return {        "message": "Student created successfully",        "student": data    }
```

409 Conflict

**How does it work?**

1. Check existing students.
2. Compare their IDs with the incoming ID.
3. If ID exists, raise an error.
4. If ID doesn't exist, save the student.

### **C. Handle other errors using try-except**

```
@app.post("/students")def create_student(student: Student):    try:        data = student.model_dump()        students.append(data)        return {"message": "Student added"}    except Exception:        raise HTTPException(            status_code=500,            detail="Internal server error"        )
```

Important: Don't use a broad `except Exception` as a replacement for proper error handling. Catch expected errors specifically and let FastAPI handle unexpected errors.

## **6. Important HTTP status codes for POST**

| Status | Meaning               | When used                 |
| ------ | --------------------- | ------------------------- |
| 200    | OK                    | Successful operation      |
| 201    | Created               | New record created        |
| 400    | Bad Request           | Invalid business request  |
| 401    | Unauthorized          | Not logged in             |
| 403    | Forbidden             | No permission             |
| 404    | Not Found             | Required resource missing |
| 409    | Conflict              | Duplicate record          |
| 422    | Validation Error      | Invalid request data      |
| 500    | Internal Server Error | Unexpected backend error  |

## **7. How to handle duplicate data in real databases?**

This is important for interviews and real projects.

| Database   | Duplicate prevention |
| ---------- | -------------------- |
| MongoDB    | Unique index         |
| PostgreSQL | UNIQUE constraint    |
| MySQL      | UNIQUE constraint    |

**Why not only use Python&#x20;**`if`**&#x20;condition?**

Imagine two users send the same email simultaneously.

Both requests might check the database before either saves the record. Both can pass the check.

This is called a race condition.

Therefore, use a database-level unique constraint/index as the final protection.

Example MongoDB:

```
db.students.create_index("id", unique=True)
```

Example PostgreSQL:

```
CREATE TABLE students (
    id VARCHAR(20) PRIMARY KEY,
    name VARCHAR(50),
    age INT
);
```

Here, `PRIMARY KEY` prevents duplicate IDs.

## **8. Other important POST concepts**

| Concept          | Explanation                            |
| ---------------- | -------------------------------------- |
| Request body     | Data sent from frontend                |
| Request model    | Pydantic model for input               |
| Response model   | Pydantic model for output              |
| `HTTPException`  | Sends a controlled HTTP error          |
| `status_code`    | Sets HTTP response status              |
| `response_model` | Defines and filters response structure |
| Duplicate check  | Prevents repeated records              |
| Database commit  | Saves database transaction             |
| `try-except`     | Handles expected runtime errors        |

### **Request model vs Response model**

You can use separate models for input and output.

```
class StudentCreate(BaseModel):    name: str    age: int    email: strclass StudentResponse(BaseModel):    id: int    name: str    age: int    email: str
```

```
@app.post("/students", response_model=StudentResponse, status_code=201)def create_student(student: StudentCreate):    return {        "id": 1,        **student.model_dump()    }
```

Why separate them?

- `StudentCreate`: What frontend must send.
- `StudentResponse`: What backend returns.
- Backend can generate the ID instead of asking the frontend to send it.

## **9. React frontend – How to send POST request?**

Using Axios:

```
import axios from "axios";

const student = {
    name: "Rahul",
    age: 22,
    email: "rahul@gmail.com"
};

try {
    const response = await axios.post(
        "http://127.0.0.1:8000/students",
        student
    );

    console.log(response.data);

} catch (error) {
    console.log(error.response?.data);
}
```

Here:

- First argument = API URL.
- Second argument = Request body.
- `response.data` = Backend response.
- `catch` = Handles API errors.

## **10. POST request interview revision checklist**

| Question                     | Quick answer                        |
| ---------------------------- | ----------------------------------- |
| What is POST?                | Sends data to create a resource     |
| How to create POST API?      | `@app.post()`                       |
| How to receive JSON?         | Pydantic model parameter            |
| Who validates data?          | FastAPI + Pydantic                  |
| How to convert data?         | `model_dump()`                      |
| How to return success?       | `return`                            |
| Success status?              | 201 Created                         |
| How to handle invalid data?  | Automatic 422 validation            |
| How to handle duplicates?    | Check + database unique constraint  |
| How to raise custom errors?  | `HTTPException`                     |
| How to send POST from React? | `axios.post(url, data)`             |
| Does POST always create?     | No, it can also submit/process data |

**One important difference to remember:**

- POST → Usually create a new record.
- GET → Read records.
- PUT → Replace/update a resource.
- PATCH → Partially update a resource.
- DELETE → Remove a resource.
