# **Request Body in FastAPI**

**Request body** means the data that the client sends to the backend/API.

For example, when a user registers, the frontend sends their name, email and password to FastAPI through the request body.

## **1. Why do we need a request body?**

Suppose you are creating a Student Management application.

A user wants to add a student:

```
{
    "name": "Rahul",
    "age": 22,
    "course": "Python",
    "marks": 90
}
```

Where does this data go?

**React Frontend**

User fills the student form

POST request + request body

**FastAPI Backend**

Receives and validates data using Pydantic

**Database**

Stores student information

Without a request body, the backend won't receive the form data in the usual way for creating or updating records.

## **2. How to use a request body in FastAPI?**

**Step 1: Import BaseModel**

```
from fastapi import FastAPIfrom pydantic import BaseModelapp = FastAPI()
```

**Step 2: Create a Pydantic model**

```
class Student(BaseModel):    name: str    age: int    course: str    marks: int
```

This defines which data the API expects.

**Step 3: Create a POST API**

```
@app.post("/students")def create_student(student: Student):    return {        "message": "Student created successfully",        "student": student.model_dump()    }
```

Here:

- `@app.post()` → Creates a POST API endpoint.
- `student: Student` → Receives request body data and validates it.
- `student.model_dump()` → Converts the Pydantic object into a dictionary.

**Step 4: Send data**

Open FastAPI Swagger documentation:

`http://127.0.0.1:8000/docs`

Select POST `/students`, click Try it out and enter:

```
{
    "name": "Rahul",
    "age": 22,
    "course": "Python",
    "marks": 90
}
```

Click Execute.

**Expected response:**

```
{
    "message": "Student created successfully",
    "student": {
        "name": "Rahul",
        "age": 22,
        "course": "Python",
        "marks": 90
    }
}
```

## **3. What happens internally?**

When you send the request:

1. Frontend sends JSON data to `/students`.
2. FastAPI receives the request body.
3. FastAPI reads the `Student` model.
4. Pydantic checks the fields and data types.
5. If valid, FastAPI creates a Student object.
6. Your function executes and returns a response.

If validation fails, FastAPI automatically returns a `422 Unprocessable Entity` response.

## **4. Different types of request body examples**

**Example A: User registration**

```
class User(BaseModel):    username: str    email: str    password: str@app.post("/register")def register(user: User):    return user.model_dump(exclude={"password"})
```

Used when a user submits registration details.

**Example B: Product creation**

```
class Product(BaseModel):    name: str    price: float    quantity: int@app.post("/products")def create_product(product: Product):    return product.model_dump()
```

Used when adding a new product.

**Example C: Update student details**

```
class StudentUpdate(BaseModel):    name: str    age: int@app.put("/students/{student_id}")def update_student(student_id: int, student: StudentUpdate):    return {        "id": student_id,        "updated_data": student.model_dump()    }
```

Here:

- `student_id` comes from the URL path.
- `student` comes from the request body.

## **5. Request body vs Path vs Query parameters**

This is very important for FastAPI interviews.

| Feature         | Request Body       | Path Parameter      | Query Parameter  |
| --------------- | ------------------ | ------------------- | ---------------- |
| Purpose         | Send data          | Identify a resource | Filter or search |
| Example         | Student details    | Student ID          | Course           |
| Location        | JSON body          | URL path            | URL after `?`    |
| FastAPI example | `student: Student` | `id: int`           | `course: str`    |

Example combining all three:

```
@app.put("/students/{student_id}")def update_student(    student_id: int,    course: str,    student: Student):    return {        "id": student_id,        "course_filter": course,        "student": student.model_dump()    }
```

Request URL:

```
/students/101?course=Python
```

Request body:

```
{
    "name": "Rahul",
    "age": 22,
    "course": "Python",
    "marks": 90
}
```

## **6. Important FastAPI request body rules**

\| Rule | Explanation |\
\|---|---|\
\| Pydantic model | FastAPI treats a model parameter as request body |\
\| `int`, `str`, `float` | Usually treated as query parameters unless explicitly marked otherwise |\
\| Path parameter | Must match the route path |\
\| Required fields | Missing required fields cause validation errors |\
\| Optional fields | Use `str | None = None` |\
\| Default values | Fields with defaults are not required |\
\| Multiple body models | FastAPI can accept multiple body parameters |\
\| GET request | Generally avoid using a request body; support is not consistent across clients |

## **7. What if we don't use Pydantic?**

You can receive raw data using `Request`:

```
from fastapi import Request@app.post("/students")async def create_student(request: Request):    data = await request.json()    return data
```

But you lose automatic Pydantic model validation and type checking. You must validate the data yourself.

That's why Pydantic models are recommended for structured request bodies.

## **8. Quick revision checklist**

| Question               | Answer                         |
| ---------------------- | ------------------------------ |
| What is request body?  | Data sent by client to backend |
| Why?                   | To create or update records    |
| Where?                 | Inside HTTP request            |
| Which method?          | Commonly POST, PUT, PATCH      |
| How in FastAPI?        | Pydantic model parameter       |
| Who validates?         | Pydantic through FastAPI       |
| Invalid data?          | Usually 422 error              |
| Convert to dictionary? | `model_dump()`                 |

**Remember this simple flow:**

`React Form → JSON Request Body → FastAPI → Pydantic Validation → Python Function → Database → Response`
