# `@field_validator`**&#x20;in Pydantic – Simple Explanation**

## **1. What is&#x20;**`@field_validator`**?**

`@field_validator` is used to write **our own custom validation rules** for a particular field in a Pydantic model.

Hindi: जेव्हा आपल्याला स्वतःचे validation rules लावायचे असतात, तेव्हा `@field_validator` वापरतो.

## **2. Why do we use it?**

Suppose:

- Name should not contain numbers.
- Age must be at least 18.
- Password must contain at least 8 characters.

For these custom rules, we use `@field_validator`.

## **3. How to use it?**

Example: Validate student age.

```
from pydantic import BaseModel, field_validatorclass Student(BaseModel):    name: str    age: int    @field_validator("age")    @classmethod    def validate_age(cls, value):        if value < 18:            raise ValueError("Age must be 18 or above")        return value
```

**Understand each line:**

| Code                      | Meaning                       |
| ------------------------- | ----------------------------- |
| `@field_validator("age")` | Apply validation to age field |
| `@classmethod`            | Validator receives the class  |
| `cls`                     | Current model class           |
| `value`                   | Incoming age value            |
| `raise ValueError()`      | Reject invalid data           |
| `return value`            | Accept valid data             |

## **4. What happens when we send data?**

Valid data

```
{
  "name": "Vibha",
  "age": 25
}
```

Result: Accepted.

Invalid data

```
{
  "name": "Vibha",
  "age": 15
}
```

Result:

```
ValueError: Age must be 18 or above
```

FastAPI returns a 422 validation error.

## **5. What if we don't use&#x20;**`@field_validator`**?**

Without it:

```
class Student(BaseModel):    name: str    age: int
```

Pydantic checks the data type, but it doesn't know that age must be 18 or above.

With `@field_validator`, we can add that custom rule.

## **6. Quick revision**

| Concept            | Purpose                       |
| ------------------ | ----------------------------- |
| `BaseModel`        | Create data model             |
| `Field()`          | Add built-in validation rules |
| `EmailStr`         | Validate email format         |
| `@field_validator` | Add custom validation         |
| `ValueError`       | Reject invalid values         |
| `return value`     | Return validated value        |

**Remember the difference:**

- `Field()` → Ready-made validation rules.
- `@field_validator` → Your own validation logic.

One important rule: In Pydantic V2, use `@field_validator` with `@classmethod` for this pattern. Always return the validated value.

**Yes, recommended in Pydantic V2.** But you don't always need to write `@classmethod` explicitly.

Pydantic can automatically recognize the validator method as a class method when you use the standard `@field_validator` pattern.

### **Recommended way**

```
from pydantic import BaseModel, field_validatorclass Student(BaseModel):    age: int    @field_validator("age")    @classmethod    def check_age(cls, value):        if value < 18:            raise ValueError("Age must be 18+")        return value
```

### **Can we skip&#x20;**`@classmethod`**?**

Yes, this also works in Pydantic V2:

```
@field_validator("age")def check_age(cls, value):    if value < 18:        raise ValueError("Age must be 18+")    return value
```

Pydantic automatically applies class-method behavior based on the `cls` parameter.

**Remember:**

- `cls` = Current model class.
- `self` = Current object instance.
- `@classmethod` = Method works with the class.

**My recommendation:** Always write `@classmethod` explicitly with `@field_validator` when using `cls`. It makes your code easier to understand.
