Yes! **SQLAlchemy is widely used in professional Python backend projects**, especially with FastAPI and PostgreSQL.

For learning and building projects, I recommend learning SQLAlchemy along with SQL.

## **1. Psycopg vs SQLAlchemy – which is more useful?**

| Psycopg                      | SQLAlchemy                                   |
| ---------------------------- | -------------------------------------------- |
| Direct PostgreSQL driver     | Python SQL toolkit and ORM                   |
| You write SQL queries        | You can work with Python classes and objects |
| More manual SQL              | Less manual SQL for common operations        |
| Good for learning direct SQL | Good for larger applications                 |

**What is ORM?**

ORM = Object Relational Mapper.

In simple words: ORM allows you to work with database tables using Python classes and objects instead of writing every SQL query manually.

Example:

SQL query:

```
SELECT * FROM students;
```

SQLAlchemy:

```
db.query(StudentDB).all()
```

Both retrieve student records.

## **Step 4: Understand&#x20;**`.all()`**,&#x20;**`.first()`**&#x20;and&#x20;**`.scalar()`

These methods retrieve data from database queries.

| Method      | Meaning                                   | Example          |
| ----------- | ----------------------------------------- | ---------------- |
| `.all()`    | Returns all matching rows                 | `query.all()`    |
| `.first()`  | Returns the first matching row            | `query.first()`  |
| `.scalar()` | Returns the first column of the first row | `query.scalar()` |

## **Step 5: Create Base class**

```
class Base(DeclarativeBase):    pass
```

- `class` = Creates a Python class.
- `Base` = Name of your class.
- `DeclarativeBase` = SQLAlchemy's parent class for database models.
- `(DeclarativeBase)` = Inherits features from DeclarativeBase.
- `pass` = Does nothing; used because the class body is empty.

**Why use Base?**

All your database model classes inherit from `Base`, so SQLAlchemy knows which classes represent database tables.

## **Step 7: Create table in PostgreSQL**

```
Base.metadata.create_all(bind=engine)
```

Meaning: Creates all database tables defined by classes inheriting from `Base`, if those tables do not already exist.

Understand the terms:

- `Base` = Parent model class.
- `metadata` = Collection of table definitions.
- `create_all()` = Creates tables in the database.
- `bind=engine` = Tells SQLAlchemy which database engine to use.

```
print("Table ready...")
```

Prints a success message in the terminal.

Important: create_all() creates missing tables; it does not automatically update existing table structures. Use Alembic for database migrations.

## **Step 8: Create Session**


Creates a session factory connected to your database engine.

**What is a Session?**

A Session is an object that manages database operations such as inserting, reading, updating and deleting records.

Remember:

- Engine = Database connection manager.
- SessionLocal = Factory that creates sessions.
- `db` = Actual session used to perform database operations.

```

```

Creates a new database session and stores it in the `db` variable.

# **3. One important improvement in your code**

You opened a session:

```
db = SessionLocal()
```

But you didn't close it.

After completing database operations, close it:

```
db.close()
```

Better practice is to use:

```
with SessionLocal() as db:    # Perform database operations here    pass
```

This automatically closes the session when the block finishes.
