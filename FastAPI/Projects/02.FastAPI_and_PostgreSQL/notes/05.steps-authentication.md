# **Part 3: First understand the database changes**

We already have a `student_records` table.

Now we need another table called `users`.

Why?

Because students and application users are different things.

- `student_records` stores student information.
- `users` stores login and account information.

For example:

| id | name  | email            | password_hash |
| -- | ----- | ---------------- | ------------- |
| 1  | Rahul | rahul\@gmail.com | $argon2id$... |
| 2  | Priya | priya\@gmail.com | $argon2id$... |

Notice: We store `password_hash`, NOT the original password.

## **Part 4: Create the User SQLAlchemy model**

**File:** `app/models/user.py`

```
from sqlalchemy import Column, Integer, Stringfrom app.database import Baseclass User(Base):    __tablename__ = "users"    id = Column(Integer, primary_key=True, index=True)    name = Column(String(50), nullable=False)    email = Column(String, unique=True, nullable=False, index=True)    hashed_password = Column(String, nullable=False)    role = Column(String, default="user", nullable=False)
```

### **Explanation**

| Code              | Meaning                         |
| ----------------- | ------------------------------- |
| `__tablename__`   | PostgreSQL table name           |
| `id`              | Unique user ID                  |
| `name`            | User's name                     |
| `email`           | Unique email for login          |
| `hashed_password` | Encrypted-looking password hash |
| `role`            | User permission: user or admin  |

**Why&#x20;**`hashed_password`**?**

Suppose a user registers with:

```
Email: rahul@gmail.com
Password: Rahul@123
```

We should never store `Rahul@123` directly in the database.

Instead, we convert it into a password hash and store that hash.

Hindi: Password hashing ka matlab original password ko ek secure hash value mein convert karna. Original password database mein save nahi karna.

## **Part 5: Create Pydantic schemas**

**File:** `app/schemas/user.py`

```
from pydantic import BaseModel, EmailStr, Field# Registration inputclass UserCreate(BaseModel):    name: str = Field(..., min_length=2, max_length=50)    email: EmailStr    password: str = Field(..., min_length=8)# User responseclass UserResponse(BaseModel):    id: int    name: str    email: EmailStr    role: str
```

### **Why separate schemas?**

You might wonder: Why not use the SQLAlchemy `User` model directly?

Because both have different jobs:

- SQLAlchemy model → Database mein data kaise store hoga.
- Pydantic schema → API se kaunsa data accept aur return hoga.

For example, registration accepts `password`, but the response must never return `hashed_password`.

This separation protects sensitive information.

## **Part 7: Create the security file**

**File:** `app/utils/security.py`

This file handles two important things:

1. Password hashing.
2. JWT token creation.

### **A. Password hashing**

```
from pwdlib import PasswordHashpassword_hash = PasswordHash.recommended()def hash_password(password: str):    return password_hash.hash(password)def verify_password(plain_password: str, hashed_password: str):    return password_hash.verify(        plain_password,        hashed_password    )
```

**How does it work?**

Registration:

```
password = "Rahul@123"hashed = hash_password(password)print(hashed)
```

Database stores the hash, not the original password.

Login:

```
verify_password("Rahul@123", hashed)
```

Output:

```
True
```

If the password is incorrect:

```
verify_password("Wrong@123", hashed)
```

Output:

```
False
```

Hindi: Registration ke time password hash hoga. Login ke time entered password ko stored hash ke against verify karenge.

### **B. JWT token creation**

Add this below the password functions in the same file.

First, `.env` file:

```
SECRET_KEY=your_generated_secret_key
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
```

Generate a strong secret key using:

```
py -c "import secrets; print(secrets.token_urlsafe(32))"
```

Copy the generated value into `.env`.

Never upload `.env` to GitHub.

Now JWT code:

```
import osimport jwtfrom datetime import datetime, timedelta, timezonefrom dotenv import load_dotenvload_dotenv()SECRET_KEY = os.getenv("SECRET_KEY")ALGORITHM = os.getenv("ALGORITHM", "HS256")ACCESS_TOKEN_EXPIRE_MINUTES = int(    os.getenv("ACCESS_TOKEN_EXPIRE_MINUTES", "30"))def create_access_token(data: dict):    to_encode = data.copy()    expire = datetime.now(timezone.utc) + timedelta(        minutes=ACCESS_TOKEN_EXPIRE_MINUTES    )    to_encode.update({"exp": expire})    token = jwt.encode(        to_encode,        SECRET_KEY,        algorithm=ALGORITHM    )    return token
```

### **Understand JWT code**

Suppose we call:

```
create_access_token({"sub": "1"})
```

Here:

- `data` → User information to put inside token.
- `sub` → Subject, identifies the user.
- `exp` → Token expiry time.
- `SECRET_KEY` → Secret used to sign the token.
- `HS256` → Signing algorithm.

The function returns a JWT token.

## **Part 8: Create authentication dependencies**

**File:** `app/utils/dependencies.py`

This is one of the most important files.

Why?

Every time a user accesses a protected API, FastAPI must check whether the user has a valid JWT token.

Instead of writing token verification code in every endpoint, we create one reusable dependency.

```
from fastapi import Depends, HTTPException, statusfrom fastapi.security import OAuth2PasswordBearerfrom sqlalchemy.orm import Sessionimport jwtfrom jwt.exceptions import InvalidTokenErrorfrom app.database import get_dbfrom app.models.user import Userfrom app.utils.security import SECRET_KEY, ALGORITHMoauth2_scheme = OAuth2PasswordBearer(    tokenUrl="/auth/login")def get_current_user(    token: str = Depends(oauth2_scheme),    db: Session = Depends(get_db)):    try:        payload = jwt.decode(            token,            SECRET_KEY,            algorithms=[ALGORITHM]        )        user_id = payload.get("sub")        if user_id is None:            raise InvalidTokenError("Missing user ID")    except InvalidTokenError:        raise HTTPException(            status_code=status.HTTP_401_UNAUTHORIZED,            detail="Invalid or expired token",            headers={"WWW-Authenticate": "Bearer"}        )    user = db.get(User, int(user_id))    if user is None:        raise HTTPException(            status_code=401,            detail="User not found"        )    return user
```

### **How does it work?**

Suppose the React frontend sends:

```
GET /students
Authorization: Bearer eyJhbGciOiJIUzI1Ni...
```

FastAPI:

1. Receives the token.
2. Extracts it using `oauth2_scheme`.
3. Decodes and verifies the JWT.
4. Checks whether the token has expired.
5. Gets the user ID from `sub`.
6. Finds the user in PostgreSQL.
7. Returns the user object.

If anything is invalid, it returns HTTP 401.

### **Understand this important line**

```
user: User = Depends(get_current_user)
```

Hindi:

Jab bhi endpoint execute hoga, FastAPI pehle `get_current_user()` execute karega.

Agar user valid hai, toh current user ka database object endpoint ko milega.

Agar invalid hai, toh endpoint execute hi nahi hoga.

## **Part 9: Create Authentication Router**

**File:** `app/routers/auth.py`

Now we create two endpoints:

- Register
- Login

```
from fastapi import APIRouter, Depends, HTTPException, statusfrom sqlalchemy.orm import Sessionfrom fastapi.security import OAuth2PasswordRequestFormfrom app.database import get_dbfrom app.models.user import Userfrom app.schemas.user import UserCreate, UserResponsefrom app.utils.security import (    hash_password,    verify_password,    create_access_token)router = APIRouter(prefix="/auth", tags=["Authentication"])
```

### **A. Registration API**

Add this below the imports:

```
@router.post(    "/register",    response_model=UserResponse,    status_code=201)def register_user(    user_data: UserCreate,    db: Session = Depends(get_db)):    existing_user = db.query(User).filter(        User.email == user_data.email    ).first()    if existing_user:        raise HTTPException(            status_code=400,            detail="Email already registered"        )    new_user = User(        name=user_data.name,        email=user_data.email,        hashed_password=hash_password(user_data.password)    )    db.add(new_user)    db.commit()    db.refresh(new_user)    return new_user
```

**What happens here?**

| Step | Code              | Work                        |
| ---- | ----------------- | --------------------------- |
| 1    | `user_data`       | Receives registration data  |
| 2    | `db.query()`      | Checks whether email exists |
| 3    | `hash_password()` | Hashes password             |
| 4    | `User()`          | Creates database object     |
| 5    | `db.add()`        | Adds user to session        |
| 6    | `db.commit()`     | Saves user in PostgreSQL    |
| 7    | `db.refresh()`    | Refreshes database object   |

Notice that we don't pass `role` from the registration request. A normal user must not be allowed to register themselves as an admin.

### **B. Login API**

Add this below registration:

```
@router.post("/login")def login_user(    form_data: OAuth2PasswordRequestForm = Depends(),    db: Session = Depends(get_db)):    user = db.query(User).filter(        User.email == form_data.username    ).first()    if not user:        raise HTTPException(            status_code=401,            detail="Invalid email or password"        )    if not verify_password(        form_data.password,        user.hashed_password    ):        raise HTTPException(            status_code=401,            detail="Invalid email or password"        )    access_token = create_access_token(        data={"sub": str(user.id)}    )    return {        "access_token": access_token,        "token_type": "bearer"    }
```

### **Why&#x20;**`form_data.username`**&#x20;instead of email?**

`OAuth2PasswordRequestForm` expects two form fields:

- `username`
- `password`

We use the `username` field to send the user's email.

For example:

```
username = rahul@gmail.com
password = Rahul@123
```

If credentials are correct, the API returns:

```
{
    "access_token": "eyJhbGciOiJIUzI1Ni...",
    "token_type": "bearer"
}
```

This is the JWT token the frontend will use.

## **Part 11: Add Authorization (Admin vs Normal User)**

We have authentication working conceptually. Now we need to control permissions.

Create this function at the bottom of:

**File:** `app/utils/dependencies.py`

```
def require_admin(    current_user: User = Depends(get_current_user)):    if current_user.role != "admin":        raise HTTPException(            status_code=403,            detail="Admin access required"        )    return current_user
```

### **Understand the difference**

- `get_current_user()` → Checks whether the user is logged in.
- `require_admin()` → Checks whether the logged-in user is an admin.

HTTP status codes:

| Status | Meaning                           |
| ------ | --------------------------------- |
| 200    | Successful                        |
| 201    | Created                           |
| 401    | Not authenticated                 |
| 403    | Authenticated, but not authorized |
| 404    | Not found                         |

**Important security points before production:**

- Keep `.env` secret and validate that `SECRET_KEY` is configured.
- Use HTTPS in production.
- Use a strong password policy and rate-limit login attempts.
- Never expose password hashes.
- JWT logout needs additional handling if you want immediate token revocation; expiry alone does not invalidate a token before its expiration.
- Use Alembic migrations when your database schema evolves; `create_all()` does not update existing tables.
