For a **FastAPI + PostgreSQL project**, I recommend using a modular folder structure. It keeps your code clean, organized, reusable, and easy to maintain as the project grows.

Let's understand it from beginner to professional level.

## **1. Recommended folder structure**

**fastapi_postgresql_project/**

**app/**

Main application

**core/**

Configuration and security

**database/**

PostgreSQL connection

**models/**

SQLAlchemy database models

**schemas/**

Pydantic validation

**crud/**

Database operations

**routers/**

API endpoints

**services/**

Business logic

**utils/**

Helper functions

**tests/**

Test cases

**main.py**

Application entry point

**requirements.txt**

Installed packages

**.env**

Environment variables

**.gitignore**

Files Git should ignore

**README.md**

Project documentation

## **2. What is the purpose of each folder?**

| Folder/file | Purpose                      |
| ----------- | ---------------------------- |
| `core/`     | Settings, JWT, security      |
| `database/` | Database connection          |
| `models/`   | Database table structure     |
| `schemas/`  | Request/response validation  |
| `crud/`     | Create, read, update, delete |
| `routers/`  | API endpoints                |
| `services/` | Business logic               |
| `utils/`    | Reusable helper functions    |
| `tests/`    | Testing APIs                 |

### **Important difference: Models vs Schemas vs CRUD vs Routers**

**1. Models – Database structure**

Defines PostgreSQL tables using SQLAlchemy.

```
# models/student.pyfrom sqlalchemy import Column, Integer, Stringfrom app.database.base import Baseclass Student(Base):    __tablename__ = "students"    id = Column(Integer, primary_key=True)    name = Column(String(50))    age = Column(Integer)
```

**2. Schemas – Data validation**

Defines what data the API accepts and returns.

```
# schemas/student.pyfrom pydantic import BaseModelclass StudentCreate(BaseModel):    name: str    age: intclass StudentResponse(StudentCreate):    id: int    model_config = {"from_attributes": True}
```

**3. CRUD – Database operations**

Contains database queries.

```
# crud/student.pyfrom app.models.student import Studentdef create_student(db, student):    new_student = Student(**student.model_dump())    db.add(new_student)    db.commit()    db.refresh(new_student)    return new_student
```

**4. Routers – API endpoints**

Defines API URLs.

```
# routers/student.pyfrom fastapi import APIRouter, Dependsfrom sqlalchemy.orm import Sessionfrom app.database.connection import get_dbfrom app.schemas.student import StudentCreatefrom app.crud.student import create_studentrouter = APIRouter(prefix="/students", tags=["Students"])@router.post("/")def add_student(    student: StudentCreate,    db: Session = Depends(get_db)):    return create_student(db, student)
```

**5. Database – PostgreSQL connection**

```
# database/connection.pyfrom sqlalchemy import create_enginefrom sqlalchemy.orm import sessionmakerDATABASE_URL = "postgresql+psycopg://postgres:password@localhost:5432/student_db"engine = create_engine(DATABASE_URL)SessionLocal = sessionmaker(    autocommit=False,    autoflush=False,    bind=engine)def get_db():    db = SessionLocal()    try:        yield db    finally:        db.close()
```

For an actual project, read the database URL from `.env`, not directly from Python code.

## **3. main.py – Application entry point**

```
# app/main.pyfrom fastapi import FastAPIfrom app.routers import studentapp = FastAPI()app.include_router(student.router)@app.get("/")def home():    return {"message": "FastAPI PostgreSQL is running"}
```

Run the application from the project root:

```
uvicorn app.main:app --reload
```

Open:

- `http://127.0.0.1:8000`
- `http://127.0.0.1:8000/docs`

```
pip freeze > requirements.txt
```

## **5. How does the complete flow work?**

**Frontend / Postman**

Sends API request

**Router**

Receives API request

**Schema**

Validates incoming data

**CRUD / Service**

Performs database operations and business logic

**Model + Database Connection**

Works with PostgreSQL tables

**PostgreSQL**

Stores and retrieves data

## **7. What should you learn first?**

My recommended order:

1. FastAPI project structure
2. PostgreSQL connection
3. SQLAlchemy models
4. Pydantic schemas
5. CRUD operations
6. Routers and API endpoints
7. Alembic migrations
8. JWT authentication
9. Error handling
10. Testing and Docker

**My recommendation:** Start with a Student Management System using FastAPI + PostgreSQL. Implement Create, Read, Update, Delete (CRUD), then add JWT authentication.

This will give you practical experience with the same architecture used in larger backend projects.
