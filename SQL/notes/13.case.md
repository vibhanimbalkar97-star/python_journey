# **CASE in SQL — Beginner to Pro (PostgreSQL)**

`CASE` is used to apply **conditions in SQL and return different results based on those conditions**.

Think of it like `if – else if – else` in JavaScript or Python.

**Hindi:** Condition true hai toh ek result do, false hai toh doosra result do.

## **1. Basic CASE syntax**

```
SELECT
    column_name,
    CASE
        WHEN condition THEN result
        WHEN condition THEN result
        ELSE result
    END AS alias_name
FROM table_name;
```

Let's use this `students` table:

| id | name  | marks |
| -- | ----- | ----- |
| 1  | Amit  | 85    |
| 2  | Priya | 45    |
| 3  | Rahul | 70    |
| 4  | Neha  | 30    |
| 5  | Raj   | 95    |

## **2. Simple CASE with one condition**

```
SELECT
    name,
    marks,
    CASE
        WHEN marks >= 40 THEN 'Pass'
        ELSE 'Fail'
    END AS result
FROM students;
```

Result:

| name  | marks | result |
| ----- | ----- | ------ |
| Amit  | 85    | Pass   |
| Priya | 45    | Pass   |
| Rahul | 70    | Pass   |
| Neha  | 30    | Fail   |
| Raj   | 95    | Pass   |

**How it works:**

- If marks are 40 or more → Pass.
- Otherwise → Fail.

## **3. CASE with multiple WHEN conditions**

Use multiple conditions to create categories.

```
SELECT
    name,
    marks,
    CASE
        WHEN marks >= 90 THEN 'Excellent'
        WHEN marks >= 75 THEN 'Very Good'
        WHEN marks >= 60 THEN 'Good'
        WHEN marks >= 40 THEN 'Pass'
        ELSE 'Fail'
    END AS grade
FROM students;
```

Result:

| name  | marks | grade     |
| ----- | ----- | --------- |
| Amit  | 85    | Very Good |
| Priya | 45    | Pass      |
| Rahul | 70    | Good      |
| Neha  | 30    | Fail      |
| Raj   | 95    | Excellent |

Important trick

SQL checks conditions from top to bottom. Once a condition is true, it returns that result and stops checking.

Put higher ranges first.

Wrong order:

```
CASE
    WHEN marks >= 40 THEN 'Pass'
    WHEN marks >= 90 THEN 'Excellent'
END
```

A student with 95 marks gets `Pass`, because the first condition is already true.

## **4. CASE without ELSE**

```
SELECT
    name,
    CASE
        WHEN marks >= 40 THEN 'Pass'
    END AS result
FROM students;
```

If no condition matches and ELSE is missing, SQL returns `NULL`.

## **5. Simple CASE vs Searched CASE**

There are two types.

### **A. Searched CASE**

Uses conditions such as `>`, `<`, `=`, `AND`, `OR`.

```
SELECT name,
CASE
    WHEN marks >= 40 THEN 'Pass'
    ELSE 'Fail'
END
FROM students;
```

### **B. Simple CASE**

Compares one expression against multiple values.

```
SELECT name,
CASE department
    WHEN 'IT' THEN 'Technology'
    WHEN 'HR' THEN 'Human Resources'
    WHEN 'Sales' THEN 'Business'
    ELSE 'Other'
END AS department_type
FROM employees;
```

| Searched CASE                  | Simple CASE               |
| ------------------------------ | ------------------------- |
| Uses conditions                | Compares equal values     |
| Supports `>`, `<`, `AND`, etc. | Uses equality comparisons |
| More flexible                  | Good for fixed categories |

## **6. CASE with WHERE**

Use CASE to create a result, and WHERE to filter actual rows.

```
SELECT
    name,
    marks,
    CASE
        WHEN marks >= 40 THEN 'Pass'
        ELSE 'Fail'
    END AS result
FROM students
WHERE marks >= 60;
```

Only students with marks 60 or above are displayed.

**Remember:** WHERE filters rows; CASE creates conditional output.

## **7. CASE with ORDER BY**

Sort records based on custom conditions.

Example: Show failed students first.

```
SELECT name, marks
FROM students
ORDER BY
    CASE
        WHEN marks < 40 THEN 1
        ELSE 2
    END;
```

Result: Failed students appear first, followed by passed students.

Another example:

```
SELECT name, marks
FROM students
ORDER BY
    CASE
        WHEN marks >= 90 THEN 1
        WHEN marks >= 60 THEN 2
        ELSE 3
    END;
```

This creates your own sorting order.

## **8. CASE with GROUP BY**

Group records based on conditional categories.

```
SELECT
    CASE
        WHEN marks >= 40 THEN 'Pass'
        ELSE 'Fail'
    END AS result,
    COUNT(*) AS total_students
FROM students
GROUP BY
    CASE
        WHEN marks >= 40 THEN 'Pass'
        ELSE 'Fail'
    END;
```

Possible output:

| result | total_students |
| ------ | -------------- |
| Pass   | 4              |
| Fail   | 1              |

## **9. CASE with aggregate functions**

Very important for interviews!

### **Count pass and fail students**

```
SELECT
    COUNT(CASE WHEN marks >= 40 THEN 1 END) AS passed,
    COUNT(CASE WHEN marks < 40 THEN 1 END) AS failed
FROM students;
```

### **Calculate total marks of passed students**

```
SELECT
    SUM(
        CASE
            WHEN marks >= 40 THEN marks
            ELSE 0
        END
    ) AS passed_marks
FROM students;
```

### **CASE with AVG**

```
SELECT
    AVG(
        CASE
            WHEN marks >= 40 THEN marks
        END
    ) AS average_pass_marks
FROM students;
```

Here, failed students return NULL and `AVG()` ignores NULL values.

## **10. CASE with UPDATE**

You can update existing data based on conditions.

```
UPDATE students
SET grade =
    CASE
        WHEN marks >= 90 THEN 'A'
        WHEN marks >= 75 THEN 'B'
        WHEN marks >= 40 THEN 'C'
        ELSE 'F'
    END;
```

This assigns grades to all students.

You can also use CASE to update different rows differently:

```
UPDATE employees
SET salary =
    CASE
        WHEN department = 'IT' THEN salary + 5000
        WHEN department = 'HR' THEN salary + 3000
        ELSE salary
    END;
```

**Trick:** Without a WHERE clause, UPDATE affects every row.

## **11. CASE with NULL**

Use `IS NULL` and `IS NOT NULL` to check NULL values.

```
SELECT
    name,
    CASE
        WHEN marks IS NULL THEN 'Not Available'
        WHEN marks >= 40 THEN 'Pass'
        ELSE 'Fail'
    END AS result
FROM students;
```

Wrong:

```
WHEN marks = NULL
```

Correct:

```
WHEN marks IS NULL
```

## **12. Nested CASE — Advanced**

A CASE inside another CASE.

```
SELECT name, marks,
CASE
    WHEN marks >= 40 THEN
        CASE
            WHEN marks >= 90 THEN 'A'
            ELSE 'B'
        END
    ELSE 'Fail'
END AS grade
FROM students;
```

Use nested CASE when a condition needs another level of checking. But for simple categories, multiple WHEN conditions are easier to read.

## **13. CASE vs COALESCE vs NULLIF**

| Function | Purpose                              | Example                                             |
| -------- | ------------------------------------ | --------------------------------------------------- |
| CASE     | Conditional logic                    | `CASE WHEN marks >= 40 THEN 'Pass' ELSE 'Fail' END` |
| COALESCE | Returns first non-NULL value         | `COALESCE(phone, 'Not given')`                      |
| NULLIF   | Returns NULL if two values are equal | `NULLIF(marks, 0)`                                  |

Examples:

```
-- Replace NULL with default text
SELECT COALESCE(phone, 'Not Available')
FROM employees;

-- Avoid division by zero
SELECT total_marks / NULLIF(subject_count, 0)
FROM results;
```

## **14. Important CASE rules and interview tricks**

| Rule                            | Remember                     |
| ------------------------------- | ---------------------------- |
| CASE must end with `END`        | Always required              |
| WHEN                            | Defines condition            |
| THEN                            | Defines result               |
| ELSE                            | Default result; optional     |
| Multiple WHEN                   | Allowed                      |
| Conditions checked              | Top to bottom                |
| No matching condition + no ELSE | Returns NULL                 |
| Result data types               | Must be compatible           |
| CASE in SELECT                  | Conditional output           |
| CASE in ORDER BY                | Custom sorting               |
| CASE in UPDATE                  | Conditional updates          |
| CASE with aggregate             | Conditional counting/summing |

**Common mistakes:**

1. Forgetting `END`.
2. Putting conditions in the wrong order.
3. Using `= NULL` instead of `IS NULL`.
4. Giving incompatible result types.

Example of incompatible types:

```
CASE
    WHEN marks >= 40 THEN 'Pass'
    ELSE 0
END
```

Here one result is text and another is integer. Use compatible types:

```
CASE
    WHEN marks >= 40 THEN 'Pass'
    ELSE 'Fail'
END
```

## **15. Interview questions**

**Q1. What is CASE in SQL?**

It is a conditional expression that returns values based on conditions.

**Q2. Is CASE similar to if-else?**

Yes. It works like if-else logic.

**Q3. What happens if ELSE is missing?**

It returns NULL when no WHEN condition matches.

**Q4. Can we use CASE in ORDER BY?**

Yes, for custom sorting.

**Q5. Can we use CASE with aggregate functions?**

Yes, for conditional counting, summing and averaging.

**Q6. Difference between simple and searched CASE?**

Simple CASE compares values for equality; searched CASE evaluates conditions.

**Q7. Can CASE be nested?**

Yes, one CASE can be inside another.

**Q8. Does CASE check all WHEN conditions?**

No. It returns the result of the first matching condition.

**Q9. Can CASE be used in UPDATE?**

Yes, to assign different values based on conditions.

**Q10. Is CASE a function?**

No. CASE is a SQL conditional expression.
