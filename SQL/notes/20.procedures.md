# **SQL Procedures in PostgreSQL – Beginner to Advanced**

Let's understand **Stored Procedures** step by step with simple examples, syntax, practical uses, interview questions and common mistakes.

## **1. What is a Procedure?**

A **Stored Procedure** is a group of SQL statements saved inside the database that you can execute whenever needed.

In simple words:

- Normal SQL query → Write and execute whenever needed.
- Procedure → Save SQL logic once and execute it whenever needed.

Example: Suppose every month you need to update employee salaries. Instead of writing the UPDATE query every time, create a procedure.

## **2. Why do we use Procedures?**

| Reason          | Meaning                                                              |
| --------------- | -------------------------------------------------------------------- |
| Reusability     | Write logic once, execute many times                                 |
| Automation      | Perform multiple database operations                                 |
| Maintainability | Keep database logic in one place                                     |
| Security        | Allow users to execute procedures without giving direct table access |
| Transactions    | Group operations using COMMIT and ROLLBACK                           |
| Business logic  | Handle operations inside the database                                |

## **3. Where are Procedures used?**

- Banking: Transfer money between accounts.
- E-commerce: Process orders and update stock.
- Employee management: Update salaries.
- Hospital: Manage patient billing.
- Inventory: Increase or decrease product quantities.

## **4. Basic syntax in PostgreSQL**

```
CREATE PROCEDURE procedure_name()
LANGUAGE plpgsql
AS $$
BEGIN
    -- SQL statements
END;
$$;
```

Understand the keywords:

| Keyword          | Meaning                             |
| ---------------- | ----------------------------------- |
| CREATE PROCEDURE | Creates a procedure                 |
| procedure_name   | Name of procedure                   |
| LANGUAGE plpgsql | Uses PostgreSQL procedural language |
| AS $$            | Starts procedure body               |
| BEGIN            | Starts statements                   |
| END              | Ends procedure body                 |
| $$               | Closes procedure body               |

**Remember:** `$$` is a dollar-quoted string delimiter. It allows you to write the procedure body without escaping every single quote.

## **5. Practical example – Create your first Procedure**

Suppose you have this table:

```
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50),
    marks INT
);
```

**Step 1: Create procedure**

```
CREATE PROCEDURE show_students()
LANGUAGE plpgsql
AS $$
BEGIN
    SELECT * FROM students;
END;
$$;
```

Important: This example is not valid as a procedure for returning query results directly to the caller. A procedure can execute SQL, but to return rows from a SELECT, use a function or a cursor. Let's use a useful procedure below.

**Step 2: Create a procedure to update marks**

```
CREATE PROCEDURE update_marks(
    p_id INT,
    p_marks INT
)
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE students
    SET marks = p_marks
    WHERE student_id = p_id;
END;
$$;
```

**Step 3: Execute procedure**

```
CALL update_marks(1, 90);
```

**Step 4: Check updated data**

```
SELECT * FROM students;
```

Now student ID 1 has 90 marks.

## **6. Procedure with IF ELSE**

Use IF/ELSE when you need conditional logic.

```
CREATE PROCEDURE check_marks(p_marks INT)
LANGUAGE plpgsql
AS $$
BEGIN
    IF p_marks >= 40 THEN
        RAISE NOTICE 'Pass';
    ELSE
        RAISE NOTICE 'Fail';
    END IF;
END;
$$;
```

Execute:

```
CALL check_marks(80);
```

Output:

```
NOTICE: Pass
```

`RAISE NOTICE` displays a message; it does not return a query result.

## **7. Procedure with multiple SQL statements**

A procedure can execute multiple operations.

```
CREATE PROCEDURE add_student(
    p_id INT,
    p_name VARCHAR(50),
    p_marks INT
)
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO students(student_id, name, marks)
    VALUES (p_id, p_name, p_marks);

    RAISE NOTICE 'Student added successfully';
END;
$$;
```

Execute:

```
CALL add_student(4, 'Neha', 85);
```

## **8. Procedure with variables**

Declare variables inside the DECLARE section.

```
CREATE PROCEDURE calculate_bonus(p_salary NUMERIC)
LANGUAGE plpgsql
AS $$
DECLARE
    bonus NUMERIC;
BEGIN
    bonus := p_salary * 0.10;

    RAISE NOTICE 'Bonus: %', bonus;
END;
$$;
```

Execute:

```
CALL calculate_bonus(50000);
```

Output:

```
Bonus: 5000.00
```

Remember:

- `:=` assigns a value to a variable in PL/pgSQL.
- `=` is used for comparison.
- `RAISE NOTICE` displays a message.

## **9. Procedure with LOOP**

Use loops when you need to repeat operations.

```
CREATE PROCEDURE print_numbers()
LANGUAGE plpgsql
AS $$
DECLARE
    i INT := 1;
BEGIN
    WHILE i <= 5 LOOP
        RAISE NOTICE '%', i;
        i := i + 1;
    END LOOP;
END;
$$;
```

Execute:

```
CALL print_numbers();
```

Output: 1, 2, 3, 4, 5.

## **10. Procedure with transaction (Advanced)**

Example: Transfer money between accounts.

```
CREATE PROCEDURE transfer_money(
    p_from INT,
    p_to INT,
    p_amount NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE accounts
    SET balance = balance - p_amount
    WHERE account_id = p_from;

    UPDATE accounts
    SET balance = balance + p_amount
    WHERE account_id = p_to;
END;
$$;
```

Execute:

```
CALL transfer_money(1, 2, 1000);
```

**Important:** Both updates should be atomic (both succeed or neither succeeds). PostgreSQL automatically runs a `CALL` inside a transaction when you don't explicitly manage one. If an error occurs, the transaction is rolled back. For production, also validate balances, account existence and amounts, and consider concurrent updates.

A procedure can use `COMMIT` and `ROLLBACK` in PostgreSQL under certain conditions, but not when `CALL` is executed inside an explicit transaction block.

## **11. How to modify and delete Procedures?**

**Modify procedure body:**

PostgreSQL uses `CREATE OR REPLACE PROCEDURE`.

```
CREATE OR REPLACE PROCEDURE check_marks(p_marks INT)
LANGUAGE plpgsql
AS $$
BEGIN
    IF p_marks >= 50 THEN
        RAISE NOTICE 'Good';
    ELSE
        RAISE NOTICE 'Needs improvement';
    END IF;
END;
$$;
```

**Delete procedure:**

```
DROP PROCEDURE check_marks(INT);
```

Why `(INT)`?

It identifies the procedure using its parameter data types. This is important when procedures have overloaded names.

**Check procedures:** In pgAdmin, expand your database → Schemas → public → Procedures. You can also use:

```
SELECT routine_name
FROM information_schema.routines
WHERE routine_type = 'PROCEDURE'
  AND routine_schema = 'public';
```

## **12. Procedure vs Function – Very important interview question**

| Procedure                                 | Function                                |
| ----------------------------------------- | --------------------------------------- |
| Created using CREATE PROCEDURE            | Created using CREATE FUNCTION           |
| Called using CALL                         | Used with SELECT or in SQL expressions  |
| Does not have a RETURNS clause            | Has a RETURNS clause                    |
| Can manage transactions in eligible calls | Cannot commit or roll back transactions |
| Used for performing operations            | Used to calculate or return values/data |

Example function:

```
CREATE FUNCTION get_total(a INT, b INT)
RETURNS INT
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN a + b;
END;
$$;
```

Execute:

```
SELECT get_total(10, 20);
```

Output: `30`

**Interview trick:**

- Procedure = Perform an operation.
- Function = Return a value or result.

A function can also perform database operations; the distinction is about how it is called, returns results and handles transactions.

## **13. Common mistakes**

| Mistake                                              | Correct approach           |
| ---------------------------------------------------- | -------------------------- |
| Using SELECT to call procedure                       | Use CALL                   |
| Forgetting LANGUAGE                                  | Specify `LANGUAGE plpgsql` |
| Forgetting BEGIN/END                                 | Include the PL/pgSQL block |
| Using `=` for assignment                             | Use `:=`                   |
| Forgetting parameter types in DROP                   | Specify signature          |
| Expecting SELECT rows from a procedure automatically | Use a function or cursor   |
| Using COMMIT inside an explicit transaction block    | Not allowed                |
