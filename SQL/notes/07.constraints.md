# **SQL Constraints in PostgreSQL – Beginner to Interview Level**

## **1. What are Constraints?**

**Constraints are rules applied to table columns to control what data can be stored.**

They help maintain correct, valid, and reliable data in a database.

**Hindi:** Constraints ka matlab hai database mein data insert ya update karte time kuch rules lagana, taaki invalid data store na ho.

Example:

- Age cannot be negative.
- Email should be unique.
- Name cannot be empty (NULL).
- Every student should have a unique ID.

## **2. Types of SQL Constraints**

PostgreSQL has these important constraints:

| Constraint  | Purpose                                                 |
| ----------- | ------------------------------------------------------- |
| NOT NULL    | Cannot store NULL                                       |
| UNIQUE      | Prevents duplicate values                               |
| PRIMARY KEY | Uniquely identifies each row                            |
| FOREIGN KEY | Connects two tables                                     |
| CHECK       | Validates a condition                                   |
| DEFAULT     | Provides a default value                                |
| EXCLUSION   | Prevents conflicting rows based on a specified operator |

Let's understand each one.

## **3. NOT NULL Constraint**

Prevents a column from storing NULL values.

**Example:**

```
CREATE TABLE students (
    id INT,
    name VARCHAR(50) NOT NULL,
    age INT
);
```

Valid:

```
INSERT INTO students (id, name, age)
VALUES (1, 'Rahul', 22);
```

Invalid:

```
INSERT INTO students (id, name, age)
VALUES (2, NULL, 23);
```

Why? Because `name` cannot be NULL.

**Remember:** NOT NULL does not prevent empty strings (`''`) or spaces (`' '`).

## **4. UNIQUE Constraint**

Prevents duplicate values in a column or combination of columns.

Example:

```
CREATE TABLE students (
    id INT,
    email VARCHAR(100) UNIQUE
);
```

Valid:

```
INSERT INTO students VALUES (1, 'rahul@gmail.com');
INSERT INTO students VALUES (2, 'priya@gmail.com');
```

Invalid:

```
INSERT INTO students VALUES (3, 'rahul@gmail.com');
```

Why? The email already exists.

**Important interview points:**

- UNIQUE prevents duplicate non-NULL values.
- PostgreSQL allows multiple NULL values by default.
- You can apply UNIQUE to multiple columns together.

**Composite UNIQUE example:**

```
CREATE TABLE enrollments (
    student_id INT,
    course_id INT,
    UNIQUE (student_id, course_id)
);
```

Meaning: A student cannot enroll in the same course twice, but can enroll in different courses.

## **5. PRIMARY KEY Constraint**

A primary key uniquely identifies each row in a table.

Example:

```
CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT
);
```

Rules:

1. Cannot contain NULL.
2. Cannot contain duplicate values.
3. Only one PRIMARY KEY constraint per table.
4. It can consist of multiple columns (composite primary key).

**Example:**

| id | name  |
| -- | ----- |
| 1  | Rahul |
| 2  | Priya |
| 3  | Amit  |

Here, `id` uniquely identifies every student.

### **Composite Primary Key**

When two or more columns together uniquely identify a row.

```
CREATE TABLE enrollments (
    student_id INT,
    course_id INT,
    PRIMARY KEY (student_id, course_id)
);
```

Here, the combination of `student_id` and `course_id` must be unique.

### **Difference: PRIMARY KEY vs UNIQUE**

| PRIMARY KEY              | UNIQUE                       |
| ------------------------ | ---------------------------- |
| Unique values            | Unique values                |
| NULL not allowed         | NULL allowed by default      |
| One constraint per table | Multiple constraints allowed |
| Identifies each row      | Prevents duplicates          |

**Interview trick:** Every primary key is unique, but every unique constraint is not a primary key.

## **6. FOREIGN KEY Constraint**

A foreign key connects two tables.

It ensures that a value in one table refers to an existing record in another table.

Example:

**Parent table – students**

```
CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(50)
);
```

**Child table – courses**

```
CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    student_id INT REFERENCES students(id),
    course_name VARCHAR(50)
);
```

Here:

- `students.id` = Primary key.
- `courses.student_id` = Foreign key.

Valid:

```
INSERT INTO students VALUES (1, 'Rahul');

INSERT INTO courses
VALUES (101, 1, 'Python');
```

Invalid:

```
INSERT INTO courses
VALUES (102, 99, 'React');
```

Why? Student ID 99 doesn't exist in the students table.

### **ON DELETE actions**

What happens when we delete a parent record that has related child records?

PostgreSQL provides these options:

| Action      | Meaning                                                                |
| ----------- | ---------------------------------------------------------------------- |
| CASCADE     | Automatically deletes related child records                            |
| SET NULL    | Sets child foreign key to NULL                                         |
| SET DEFAULT | Sets child foreign key to its default value                            |
| RESTRICT    | Prevents deletion if child records exist                               |
| NO ACTION   | Checks the constraint; normally prevents deletion if references remain |

Example:

```
CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    student_id INT REFERENCES students(id)
    ON DELETE CASCADE
);
```

If student ID 1 is deleted, its related course records are also deleted.

**Important:** `SET NULL` requires the foreign key column to allow NULL. Similarly, `SET DEFAULT` requires a suitable default value.

### **ON UPDATE**

You can also define what happens when the referenced parent key changes.

```
student_id INT REFERENCES students(id)
ON UPDATE CASCADE;
```

If the referenced student ID changes, the child records are updated automatically.

## **7. CHECK Constraint**

CHECK validates data against a condition.

Example:

```
CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT CHECK (age >= 18)
);
```

Valid:

```
INSERT INTO students
VALUES (1, 'Rahul', 22);
```

Invalid:

```
INSERT INTO students
VALUES (2, 'Priya', 15);
```

Why? Age must be 18 or above.

### **Multiple conditions**

```
CREATE TABLE employees (
    id INT PRIMARY KEY,
    age INT CHECK (age >= 18 AND age <= 60),
    salary NUMERIC(10,2) CHECK (salary > 0)
);
```

### **IN with CHECK**

```
CREATE TABLE employees (
    id INT PRIMARY KEY,
    department VARCHAR(20)
    CHECK (department IN ('IT', 'HR', 'Finance'))
);
```

Only these three department values are allowed.

**Interview point:** CHECK does not automatically prevent NULL. Use NOT NULL separately if NULL is not allowed.

## **8. DEFAULT Constraint**

Automatically provides a value when the user does not specify one.

Example:

```
CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    course VARCHAR(50) DEFAULT 'Python',
    is_active BOOLEAN DEFAULT TRUE
);
```

Insert:

```
INSERT INTO students (id, name)
VALUES (1, 'Rahul');
```

Result:

| id | name  | course | is_active |
| -- | ----- | ------ | --------- |
| 1  | Rahul | Python | TRUE      |

**Important interview trick:**

What happens if you explicitly insert NULL?

```
INSERT INTO students (id, name, course)
VALUES (2, 'Priya', NULL);
```

The course will be NULL, not Python.

Why? DEFAULT is used when a value is omitted or when you explicitly specify `DEFAULT`, not when you explicitly provide NULL.

## **9. EXCLUSION Constraint (Advanced)**

This constraint prevents two rows from conflicting according to a specified operator.

It is commonly used for scheduling and booking systems.

Example: Prevent overlapping room bookings.

PostgreSQL uses range types and the `&&` overlap operator.

```
CREATE EXTENSION IF NOT EXISTS btree_gist;

CREATE TABLE bookings (
    room_id INT,
    booking_period TSRANGE,
    EXCLUDE USING GIST (
        room_id WITH =,
        booking_period WITH &&
    )
);
```

Meaning: The same room cannot have overlapping booking periods.

For beginners, remember the purpose and syntax. You can learn GiST and range types later.

# **10. How to add constraints after creating a table?**

Very important for interviews and real projects.

We use `ALTER TABLE`.

### **Add NOT NULL**

```
ALTER TABLE students
ALTER COLUMN name SET NOT NULL;
```

Remove NOT NULL:

```
ALTER TABLE students
ALTER COLUMN name DROP NOT NULL;
```

### **Add UNIQUE**

```
ALTER TABLE students
ADD CONSTRAINT unique_email UNIQUE (email);
```

### **Add PRIMARY KEY**

```
ALTER TABLE students
ADD CONSTRAINT students_pkey PRIMARY KEY (id);
```

### **Add FOREIGN KEY**

```
ALTER TABLE courses
ADD CONSTRAINT fk_student
FOREIGN KEY (student_id)
REFERENCES students(id);
```

### **Add CHECK**

```
ALTER TABLE students
ADD CONSTRAINT check_age CHECK (age >= 18);
```

### **Add DEFAULT**

```
ALTER TABLE students
ALTER COLUMN course SET DEFAULT 'Python';
```

Remove DEFAULT:

```
ALTER TABLE students
ALTER COLUMN course DROP DEFAULT;
```

### **Remove a constraint**

```
ALTER TABLE students
DROP CONSTRAINT unique_email;
```

Remember: You need the constraint name. PostgreSQL also generates names automatically if you don't provide one.

# **11. Complete real-world example**

Let's create an employee table using multiple constraints.

```
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    age INT CHECK (age >= 18),
    salary NUMERIC(10,2) CHECK (salary > 0),
    department VARCHAR(30) DEFAULT 'IT',
    is_active BOOLEAN DEFAULT TRUE
);
```

What are we enforcing?

| Column     | Constraint        | Rule                      |
| ---------- | ----------------- | ------------------------- |
| id         | PRIMARY KEY       | Unique ID, not NULL       |
| name       | NOT NULL          | Name required             |
| email      | UNIQUE + NOT NULL | Email required and unique |
| age        | CHECK             | Must be at least 18       |
| salary     | CHECK             | Must be positive          |
| department | DEFAULT           | IT if omitted             |
| is_active  | DEFAULT           | TRUE if omitted           |

This is how constraints protect real-world application data.

# **12. Most important interview differences**

| Question                                      | Answer                                                          |
| --------------------------------------------- | --------------------------------------------------------------- |
| PRIMARY KEY vs FOREIGN KEY                    | Identifies own rows vs references another table                 |
| UNIQUE vs PRIMARY KEY                         | Both enforce uniqueness, but PK cannot be NULL                  |
| NOT NULL vs CHECK                             | NOT NULL prevents NULL; CHECK validates a condition             |
| DEFAULT vs NOT NULL                           | DEFAULT supplies a value; NOT NULL prevents missing values      |
| CASCADE vs RESTRICT                           | Automatically handles child records vs prevents parent deletion |
| Composite key                                 | Two or more columns together identify a row                     |
| Can a table have multiple UNIQUE constraints? | Yes                                                             |
| Can a table have multiple FOREIGN KEYS?       | Yes                                                             |
| Can a table have multiple PRIMARY KEYS?       | No, only one primary key constraint                             |
| Can a FOREIGN KEY contain NULL?               | Yes, unless NOT NULL is also applied                            |
