To identify the relationship from `CREATE TABLE`, look mainly at **PRIMARY KEY (PK), FOREIGN KEY (FK), and UNIQUE constraints**.

Remember: **Foreign keys tell you which tables are connected. UNIQUE and NOT NULL help determine the relationship's cardinality and optionality.**

## **1. One-to-Many (1:N)**

```
CREATE TABLE departments (
    dept_id INT PRIMARY KEY,
    dept_name VARCHAR(50)
);

CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    name VARCHAR(50),
    dept_id INT REFERENCES departments(dept_id)
);
```

**How to identify?**

- `departments.dept_id` = PK
- `employees.dept_id` = FK
- FK is NOT UNIQUE, so multiple employees can have the same department.

One-to-Many

One department → Many employees.

## **2. One-to-One (1:1)**

```
CREATE TABLE persons (
    person_id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE passports (
    passport_id INT PRIMARY KEY,
    person_id INT UNIQUE REFERENCES persons(person_id)
);
```

**How to identify?**

- `person_id` is FK.
- `person_id` also has UNIQUE.
- So one person can be linked to at most one passport.

One-to-One

One person → Zero or one passport.

## **3. Many-to-Many (M:N)**

```
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    course_name VARCHAR(50)
);

CREATE TABLE enrollments (
    student_id INT REFERENCES students(student_id),
    course_id INT REFERENCES courses(course_id),
    PRIMARY KEY (student_id, course_id)
);
```

**How to identify?**

- There are two main tables: students and courses.
- A third table: enrollments.
- Enrollments contains two foreign keys.
- Both FK columns can have multiple occurrences individually.
- Composite PK prevents duplicate combinations.

Many-to-Many

Students ↔ Enrollments ↔ Courses.

## **4. Quick identification tricks**

| What you see in CREATE TABLE | Relationship clue                                     |
| ---------------------------- | ----------------------------------------------------- |
| FK without UNIQUE            | Usually Many-to-One from FK table to referenced table |
| FK + UNIQUE                  | One-to-One (at most one)                              |
| Two FKs in a junction table  | Usually Many-to-Many                                  |
| FK referencing its own table | Self-referencing relationship                         |
| FK + NOT NULL                | Every child row must have a parent                    |
| FK without NOT NULL          | Child can have no parent (NULL)                       |

## **5. Important interview trick**

Suppose you see:

```
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT REFERENCES customers(customer_id)
);
```

Ask these questions:

1. Which column is PK? → `order_id`
2. Which column is FK? → `customer_id`
3. Which table contains FK? → `orders`
4. Can multiple orders have the same customer_id? → Yes.
5. Relationship? → One Customer to Many Orders (1:N).
