# **SQL CRUD Operations in PostgreSQL – Beginner to Interview Level**

CRUD is one of the most important SQL topics. Almost every backend application uses CRUD operations.

First, remember:

**CRUD = Create + Read + Update + Delete**

These are the four basic operations used to manage data in a database.

Let's use one example throughout: a `students` table.

| id | name  | age | course |
| -- | ----- | --- | ------ |
| 1  | Rahul | 22  | Python |
| 2  | Priya | 24  | React  |
| 3  | Amit  | 21  | SQL    |

## **1. CREATE – Add new data**

In SQL, we use the `INSERT INTO` command to add records to a table.

**Syntax:**

```
INSERT INTO table_name (column1, column2)
VALUES (value1, value2);
```

**Example:**

```
INSERT INTO students (name, age, course)
VALUES ('Rahul', 22, 'Python');
```

Output: A new student record is added.

**Important rules:**

- Text values use single quotes `' '`.
- Numbers generally don't need quotes.
- Values must match the corresponding column order.
- You can insert multiple records in one query.

**Insert multiple records:**

```
INSERT INTO students (name, age, course)
VALUES
('Rahul', 22, 'Python'),
('Priya', 24, 'React'),
('Amit', 21, 'SQL');
```

**Interview question: Can we insert data without specifying column names?**

Yes.

```
INSERT INTO students
VALUES (4, 'Neha', 23, 'Java');
```

But you must provide values for all columns in the exact table order, including generated columns where applicable. Specifying column names is generally safer.

## **2. READ – Retrieve data**

We use the `SELECT` command to fetch records from a table.

**Syntax:**

```
SELECT column_name
FROM table_name;
```

**Example 1: Get all columns**

```
SELECT * FROM students;
```

`*` means all columns.

**Example 2: Get specific columns**

```
SELECT name, age
FROM students;
```

**Example 3: Get one particular student**

```
SELECT *
FROM students
WHERE id = 1;
```

Output: Only Rahul's record.

### **Important SELECT-related clauses**

| Command  | Purpose                    |
| -------- | -------------------------- |
| WHERE    | Filter records             |
| DISTINCT | Remove duplicate results   |
| ORDER BY | Sort records               |
| LIMIT    | Restrict number of records |
| OFFSET   | Skip records               |
| AS       | Give temporary alias       |

Examples:

**WHERE – Filter data**

```
SELECT * FROM students
WHERE age > 21;
```

**DISTINCT – Get unique values**

```
SELECT DISTINCT course
FROM students;
```

**ORDER BY – Sort data**

```
SELECT * FROM students
ORDER BY age ASC;
```

- `ASC` = Ascending (small to large).
- `DESC` = Descending (large to small).

**LIMIT – Get only 2 records**

```
SELECT * FROM students
LIMIT 2;
```

**OFFSET – Skip first 2 records**

```
SELECT * FROM students
OFFSET 2;
```

**LIMIT + OFFSET – Pagination**

```
SELECT * FROM students
ORDER BY id
LIMIT 10 OFFSET 20;
```

This fetches 10 records after skipping the first 20.

## **3. UPDATE – Modify existing data**

We use the `UPDATE` command to change existing records.

**Syntax:**

```
UPDATE table_name
SET column_name = value
WHERE condition;
```

**Example: Change Rahul's age**

```
UPDATE students
SET age = 23
WHERE id = 1;
```

Now Rahul's age becomes 23.

### **Update multiple columns**

```
UPDATE students
SET age = 25,
    course = 'MERN'
WHERE id = 1;
```

### **Update multiple records**

```
UPDATE students
SET course = 'Full Stack'
WHERE age > 22;
```

All matching students will be updated.

Important interview point

**What happens if we forget WHERE?**

```
UPDATE students
SET age = 25;
```

Every row in the table gets updated!

Always check your WHERE condition before executing UPDATE.

## **4. DELETE – Remove existing data**

We use the `DELETE` command to remove records from a table.

**Syntax:**

```
DELETE FROM table_name
WHERE condition;
```

**Example: Delete Rahul's record**

```
DELETE FROM students
WHERE id = 1;
```

Only Rahul's record will be deleted.

### **Delete multiple records**

```
DELETE FROM students
WHERE age < 22;
```

All students younger than 22 will be deleted.

### **Delete all records**

```
DELETE FROM students;
```

This deletes all records, but the table structure remains.

Important interview point

What happens if we forget WHERE?

```
DELETE FROM students;
```

All rows will be deleted!

The table itself will still exist.

# **5. Difference between DELETE, TRUNCATE and DROP**

This is a very common SQL interview question.

| Command  | What it does                                      |
| -------- | ------------------------------------------------- |
| DELETE   | Deletes selected rows or all rows                 |
| TRUNCATE | Removes all rows quickly                          |
| DROP     | Deletes the entire table, including its structure |

### **DELETE**

```
DELETE FROM students
WHERE id = 2;
```

- Can delete selected rows.
- Supports WHERE.
- Table structure remains.

### **TRUNCATE**

```
TRUNCATE TABLE students;
```

- Removes all rows.
- Does not support WHERE.
- Table structure remains.
- Normally resets identity sequences in PostgreSQL.

### **DROP**

```
DROP TABLE students;
```

- Deletes the complete table.
- Data and table structure are removed.

**Easy trick to remember:**

- DELETE = Remove selected data.
- TRUNCATE = Empty the table.
- DROP = Remove the table itself.

**Interview question: Can we rollback DELETE, TRUNCATE and DROP in PostgreSQL?**

Yes, PostgreSQL supports transactional rollback for all three when executed inside an explicit transaction and not committed.

Example:

```
BEGIN;

DELETE FROM students
WHERE id = 1;

ROLLBACK;
```

The deleted record is restored.

# **6. Important INSERT, UPDATE and DELETE features**

These are useful when writing real-world backend applications.

### **A. INSERT with RETURNING**

PostgreSQL provides `RETURNING` to return the inserted record immediately.

```
INSERT INTO students (name, age, course)
VALUES ('Neha', 23, 'Python')
RETURNING *;
```

It inserts Neha and returns her record.

You can also return specific columns:

```
INSERT INTO students (name, age, course)
VALUES ('Neha', 23, 'Python')
RETURNING id, name;
```

### **B. UPDATE with RETURNING**

```
UPDATE students
SET age = 25
WHERE id = 2
RETURNING *;
```

Updates Priya's age and returns the updated record.

### **C. DELETE with RETURNING**

```
DELETE FROM students
WHERE id = 2
RETURNING *;
```

Deletes the matching record and returns the deleted data.

**Interview point:** `RETURNING` is a PostgreSQL feature that is especially useful when building APIs.

# **7. Important rules and tricky concepts**

### **Rule 1: WHERE vs HAVING**

| WHERE                                       | HAVING                                 |
| ------------------------------------------- | -------------------------------------- |
| Filters individual rows                     | Filters grouped results                |
| Used before GROUP BY                        | Used after GROUP BY                    |
| Generally used without aggregate conditions | Commonly used with aggregate functions |

Example:

```
SELECT *
FROM students
WHERE age > 21;
```

Example with HAVING:

```
SELECT course, COUNT(*)
FROM students
GROUP BY course
HAVING COUNT(*) > 2;
```

### **Rule 2: NULL values**

NULL means missing or unknown value.

You cannot check NULL using `= NULL`.

Wrong

```
SELECT *
FROM students
WHERE age = NULL;
```

Correct

```
SELECT *
FROM students
WHERE age IS NULL;
```

To find records where age is not NULL:

```
SELECT *
FROM students
WHERE age IS NOT NULL;
```

### **Rule 3: AND vs OR**

**AND:** Both conditions must be true.

```
SELECT *
FROM students
WHERE age > 20 AND course = 'Python';
```

**OR:** At least one condition must be true.

```
SELECT *
FROM students
WHERE age > 20 OR course = 'Python';
```

### **Rule 4: BETWEEN**

Used to find values within a range. Both endpoints are included.

```
SELECT *
FROM students
WHERE age BETWEEN 20 AND 25;
```

Same as:

```
WHERE age >= 20 AND age <= 25;
```

### **Rule 5: IN**

Used to check multiple possible values.

```
SELECT *
FROM students
WHERE course IN ('Python', 'React');
```

Same idea as:

```
WHERE course = 'Python'
OR course = 'React';
```

### **Rule 6: LIKE**

Used for pattern matching.

```
SELECT *
FROM students
WHERE name LIKE 'R%';
```

Finds names starting with R.

| Pattern  | Meaning               |
| -------- | --------------------- |
| `'R%'`   | Starts with R         |
| `'%a'`   | Ends with a           |
| `'%ha%'` | Contains ha           |
| `'_a%'`  | Second character is a |

PostgreSQL also supports `ILIKE` for case-insensitive pattern matching.

```
SELECT *
FROM students
WHERE name ILIKE 'r%';
```

This matches names starting with R or r.

# **8. CREATE vs INSERT – Important difference**

Beginners often confuse these two.

**CREATE** creates the table structure.

```
CREATE TABLE students (
    id INT,
    name VARCHAR(50),
    age INT,
    course VARCHAR(50)
);
```

**INSERT** adds data inside that table.

```
INSERT INTO students (id, name, age, course)
VALUES (1, 'Rahul', 22, 'Python');
```

Remember:

- CREATE = Make a table.
- INSERT = Add data.
- SELECT = Read data.
- UPDATE = Modify data.
- DELETE = Remove data.

# **9. Primary Key and Foreign Key**

These are important when working with relational databases.

### **Primary Key (PK)**

A primary key uniquely identifies each record.

```
CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT
);
```

Rules:

- Cannot contain NULL.
- Cannot contain duplicate values.
- A table has only one primary key constraint (which can contain multiple columns).

### **Foreign Key (FK)**

A foreign key connects one table to another.

Example:

**Students table**

| id | name  |
| -- | ----- |
| 1  | Rahul |
| 2  | Priya |

**Courses table**

| course_id | student_id | course |
| --------- | ---------- | ------ |
| 101       | 1          | Python |
| 102       | 2          | React  |

Here, `student_id` is a foreign key referencing `students.id`.

```
CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    student_id INT REFERENCES students(id),
    course VARCHAR(50)
);
```

Why use foreign keys?

To maintain relationships and prevent invalid references to students that don't exist.

# **10. Constraints used with CRUD**

Constraints are rules applied to table columns to maintain valid data.

| Constraint  | Purpose                  |
| ----------- | ------------------------ |
| PRIMARY KEY | Unique identification    |
| FOREIGN KEY | Connect tables           |
| NOT NULL    | Value cannot be NULL     |
| UNIQUE      | Prevent duplicate values |
| CHECK       | Apply a condition        |
| DEFAULT     | Set a default value      |

Example:

```
CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    age INT CHECK (age > 0),
    course VARCHAR(50) DEFAULT 'General'
);
```

If you insert a student without specifying course, PostgreSQL automatically uses `General`.

# **11. UPSERT – INSERT or UPDATE**

This is a useful PostgreSQL interview topic.

Suppose a student with ID 1 already exists.

You want to:

- Insert the student if ID doesn't exist.
- Update the student's name if ID already exists.

PostgreSQL provides `ON CONFLICT`.

```
INSERT INTO students (id, name, age)
VALUES (1, 'Rahul', 23)

ON CONFLICT (id)
DO UPDATE
SET name = EXCLUDED.name,
    age = EXCLUDED.age;
```

What happens?

- If ID 1 doesn't exist → INSERT.
- If ID 1 already exists → UPDATE.

`EXCLUDED` refers to the values you attempted to insert.

This is called **UPSERT** (Update + Insert).

# **12. Transactions in CRUD**

A transaction is a group of database operations treated as one logical unit.

Important commands:

| Command   | Meaning                        |
| --------- | ------------------------------ |
| BEGIN     | Start transaction              |
| COMMIT    | Save changes permanently       |
| ROLLBACK  | Undo uncommitted changes       |
| SAVEPOINT | Create a point to roll back to |

Example:

```
BEGIN;

UPDATE students
SET age = 25
WHERE id = 1;

DELETE FROM students
WHERE id = 2;

COMMIT;
```

Both operations are committed together.

If something goes wrong:

```
BEGIN;

DELETE FROM students
WHERE id = 1;

ROLLBACK;
```

The deletion is undone.

**Interview question: Why do we need transactions?**

Imagine transferring ₹1,000 from Account A to Account B.

1. Deduct ₹1,000 from A.
2. Add ₹1,000 to B.

If the first operation succeeds but the second fails, the transaction allows us to roll back the first operation.

This maintains data consistency.

# **13. How CRUD works in a real backend application**

Since you are learning Python and FastAPI, understand this flow.

Imagine a Student Management API.

**React Frontend**

User clicks Add / View / Edit / Delete

HTTP Request (API)

**FastAPI Backend**

Receives request and executes SQL query

**PostgreSQL Database**

Stores and manages student records

| User action    | HTTP method | SQL command |
| -------------- | ----------- | ----------- |
| Add student    | POST        | INSERT      |
| View students  | GET         | SELECT      |
| Edit student   | PUT / PATCH | UPDATE      |

Remember: HTTP methods and SQL commands are different things. FastAPI receives HTTP requests and uses SQL to communicate with PostgreSQL.
