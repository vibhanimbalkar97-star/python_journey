# **SQL Clauses + Operators in PostgreSQL (Beginner to Advanced)**

Let's combine SQL clauses and operators in one revision guide. These are important for writing queries and solving SQL interview questions.

## **1. Basic SQL Clauses**

| Clause   | Purpose                  | Example                      |
| -------- | ------------------------ | ---------------------------- |
| SELECT   | Choose columns           | `SELECT name`                |
| FROM     | Choose table             | `FROM employees`             |
| WHERE    | Filter rows              | `WHERE age > 25`             |
| DISTINCT | Remove duplicate results | `SELECT DISTINCT department` |
| GROUP BY | Group similar records    | `GROUP BY department`        |
| HAVING   | Filter groups            | `HAVING COUNT(*) > 2`        |
| ORDER BY | Sort records             | `ORDER BY salary DESC`       |
| LIMIT    | Restrict rows            | `LIMIT 5`                    |
| OFFSET   | Skip rows                | `OFFSET 5`                   |

## **2. Comparison Operators**

Used in WHERE to compare values.

| Operator | Meaning               | Example          |
| -------- | --------------------- | ---------------- |
| `=`      | Equal                 | `age = 25`       |
| `!=`     | Not equal             | `age != 25`      |
| `<>`     | Not equal             | `age <> 25`      |
| `>`      | Greater than          | `salary > 30000` |
| `<`      | Less than             | `age < 30`       |
| `>=`     | Greater than or equal | `age >= 25`      |
| `<=`     | Less than or equal    | `age <= 30`      |

Example:

```
SELECT *
FROM employees
WHERE salary >= 30000;
```

## **3. Logical Operators**

Used to combine or reverse conditions.

| Operator | Meaning              | Example                                  |
| -------- | -------------------- | ---------------------------------------- |
| AND      | Both conditions true | `age > 25 AND salary > 30000`            |
| OR       | At least one true    | `department = 'IT' OR department = 'HR'` |
| NOT      | Reverses condition   | `NOT age > 25`                           |

Example:

```
SELECT *
FROM employees
WHERE age > 25 AND department = 'IT';
```

**Interview trick:** AND has higher precedence than OR. Use parentheses when mixing them.

```
WHERE (department = 'IT' OR department = 'HR')
AND salary > 30000;
```

## **4. Special Filtering Operators**

These are frequently used with WHERE.

### **A. IN**

Checks whether a value matches any value in a list.

```
SELECT *
FROM employees
WHERE department IN ('IT', 'HR');
```

### **B. NOT IN**

Excludes values in a list.

```
SELECT *
FROM employees
WHERE department NOT IN ('IT', 'HR');
```

Common mistake

If the NOT IN list contains NULL, the result may be unexpected because SQL uses three-valued logic.

**Solution:** Avoid NULL in the list or use `NOT EXISTS` for subquery-based exclusion.

### **C. BETWEEN**

Checks whether a value falls within a range (inclusive).

```
SELECT *
FROM employees
WHERE salary BETWEEN 30000 AND 50000;
```

### **D. NOT BETWEEN**

```
SELECT *
FROM employees
WHERE salary NOT BETWEEN 30000 AND 50000;
```

### **E. LIKE**

Pattern matching (case-sensitive in PostgreSQL).

```
SELECT *
FROM employees
WHERE name LIKE 'R%';
```

| Pattern  | Meaning               |
| -------- | --------------------- |
| `'R%'`   | Starts with R         |
| `'%a'`   | Ends with a           |
| `'%ha%'` | Contains ha           |
| `'_a%'`  | Second character is a |

- `%` = Any number of characters.
- `_` = Exactly one character.

### **F. ILIKE**

Case-insensitive pattern matching in PostgreSQL.

```
SELECT *
FROM employees
WHERE name ILIKE 'r%';
```

Matches Rahul and rahul.

### **G. IS NULL**

Checks missing or unknown values.

```
SELECT *
FROM employees
WHERE department IS NULL;
```

### **H. IS NOT NULL**

```
SELECT *
FROM employees
WHERE department IS NOT NULL;
```

Remember: Never use `= NULL` or `!= NULL`.

## **5. Arithmetic Operators**

Used to perform mathematical calculations.

| Operator | Meaning        | Example         |
| -------- | -------------- | --------------- |
| `+`      | Addition       | `salary + 1000` |
| `-`      | Subtraction    | `salary - 1000` |
| `*`      | Multiplication | `salary * 12`   |
| `/`      | Division       | `salary / 12`   |
| `%`      | Remainder      | `salary % 2`    |

Example:

```
SELECT
    name,
    salary,
    salary * 12 AS annual_salary
FROM employees;
```

Find even IDs:

```
SELECT *
FROM employees
WHERE id % 2 = 0;
```

## **6. Aggregate Functions + GROUP BY + HAVING**

Aggregate functions calculate results across multiple rows.

| Function | Purpose |
| -------- | ------- |
| COUNT()  | Count   |
| SUM()    | Total   |
| AVG()    | Average |
| MAX()    | Highest |
| MIN()    | Lowest  |

Example:

```
SELECT department, AVG(salary)
FROM employees
GROUP BY department;
```

Filter groups:

```
SELECT department, AVG(salary)
FROM employees
GROUP BY department
HAVING AVG(salary) > 30000;
```

**Important difference:**

- WHERE filters individual rows.
- HAVING filters grouped results.

## **7. DISTINCT + ORDER BY + LIMIT**

Example: Find the top three highest-paid employees.

```
SELECT DISTINCT name, salary
FROM employees
ORDER BY salary DESC
LIMIT 3;
```

Find the second-highest distinct salary:

```
SELECT DISTINCT salary
FROM employees
ORDER BY salary DESC
LIMIT 1 OFFSET 1;
```

## **8. EXISTS and NOT EXISTS**

Used to check whether a subquery returns at least one row.

### **EXISTS**

```
SELECT *
FROM employees e
WHERE EXISTS (
    SELECT 1
    FROM departments d
    WHERE d.id = e.department_id
);
```

Returns employees whose department exists.

### **NOT EXISTS**

```
SELECT *
FROM employees e
WHERE NOT EXISTS (
    SELECT 1
    FROM departments d
    WHERE d.id = e.department_id
);
```

Returns employees without a matching department.

**Interview tip:** EXISTS is often useful for checking related records without returning their columns.

## **9. ANY and ALL**

Used with subqueries to compare one value against multiple values.

### **ANY**

Condition must be true for at least one returned value.

```
SELECT *
FROM employees
WHERE salary > ANY (
    SELECT salary
    FROM employees
    WHERE department = 'HR'
);
```

Meaning: Salary is greater than at least one HR employee's salary.

### **ALL**

Condition must be true for every returned value.

```
SELECT *
FROM employees
WHERE salary > ALL (
    SELECT salary
    FROM employees
    WHERE department = 'HR'
);
```

Meaning: Salary is greater than every HR employee's salary.

| ANY                       | ALL                        |
| ------------------------- | -------------------------- |
| At least one match        | Every value must match     |
| Similar to OR comparisons | Similar to AND comparisons |

## **10. JOIN Operators**

Used to combine multiple tables.

| JOIN            | Purpose                     |
| --------------- | --------------------------- |
| INNER JOIN      | Only matching records       |
| LEFT JOIN       | All left + matching right   |
| RIGHT JOIN      | All right + matching left   |
| FULL OUTER JOIN | All records from both sides |
| CROSS JOIN      | Every possible combination  |
| SELF JOIN       | Join a table with itself    |

Example:

```
SELECT e.name, d.department_name
FROM employees e
INNER JOIN departments d
ON e.department_id = d.id;
```

## **11. Set Operators**

Combine results from multiple SELECT statements.

| Operator  | Purpose                                    |
| --------- | ------------------------------------------ |
| UNION     | Combines and removes duplicates            |
| UNION ALL | Combines and keeps duplicates              |
| INTERSECT | Returns common rows                        |
| EXCEPT    | Returns rows in first query but not second |

Example:

```
SELECT name FROM employees
UNION
SELECT name FROM managers;
```

## **12. Advanced SQL Operators (PostgreSQL)**

Useful for experienced-level interviews.

\| Operator | Purpose | Example |\
\|---|---|---|\
\| `||` | Concatenate strings | `'Hello' || ' SQL'` |\
\| `->` | Get JSON field as JSON | `data -> 'name'` |\
\| `->>` | Get JSON field as text | `data ->> 'name'` |\
\| `@>` | JSON/array contains | `data @> '{"age":25}'` |\
\| `&&` | Arrays or ranges overlap | `ARRAY[1,2] && ARRAY[2,3]` |\
\| `~` | Regex match | `name ~ '^R'` |\
\| `~*` | Case-insensitive regex | `name ~* '^r'` |\
\| `::` | Type casting | `'25'::INT` |

Example: String concatenation.

```
SELECT name || ' - ' || department AS employee_info
FROM employees;
```

Example: JSONB.

```
SELECT *
FROM users
WHERE details ->> 'city' = 'Pune';
```

# **13. Complete SQL Query – Combine Everything**

```
SELECT
    department,
    COUNT(*) AS total_employees,
    AVG(salary) AS avg_salary
FROM employees
WHERE age >= 25
  AND salary BETWEEN 20000 AND 60000
  AND department IN ('IT', 'HR', 'Finance')
GROUP BY department
HAVING COUNT(*) >= 1
ORDER BY avg_salary DESC
LIMIT 5 OFFSET 0;
```

Understand the flow:

1. FROM → Select employees table.
2. WHERE → Filter rows.
3. GROUP BY → Group by department.
4. HAVING → Filter groups.
5. SELECT → Calculate and display results.
6. ORDER BY → Sort results.
7. LIMIT/OFFSET → Control returned rows.

# **14. Common Interview Mistakes**

| Mistake                                  | Correct approach              |
| ---------------------------------------- | ----------------------------- |
| `age = NULL`                             | `age IS NULL`                 |
| Aggregate function in WHERE              | Use HAVING or a subquery      |
| LIMIT without sorting                    | Add ORDER BY                  |
| Mixing AND/OR carelessly                 | Use parentheses               |
| NOT IN with NULL                         | Handle NULL or use NOT EXISTS |
| SELECT \* everywhere                     | Select required columns       |
| Using DISTINCT to hide JOIN errors       | Fix JOIN conditions           |
| Using OFFSET for huge pages              | Consider keyset pagination    |
| Using LIKE for case-insensitive matching | Use ILIKE in PostgreSQL       |
