# **SQL Aggregate Functions with Clauses — Beginner to Pro (PostgreSQL)**

**Aggregate functions** perform calculations on multiple rows and return a single result.

For example, if an employees table contains 5 employees, you can calculate their total salary, average salary, highest salary, etc.

## **1. Basic aggregate functions**

Assume we have this `employees` table:

| id | name  | department | salary |
| -- | ----- | ---------- | ------ |
| 1  | Amit  | IT         | 50000  |
| 2  | Priya | HR         | 40000  |
| 3  | Rahul | IT         | 60000  |
| 4  | Neha  | HR         | 45000  |
| 5  | Raj   | IT         | 55000  |

### **Main aggregate functions**

| Function  | Meaning            | Example       |
| --------- | ------------------ | ------------- |
| `COUNT()` | Counts rows/values | `COUNT(*)`    |
| `SUM()`   | Adds values        | `SUM(salary)` |
| `AVG()`   | Calculates average | `AVG(salary)` |
| `MAX()`   | Finds maximum      | `MAX(salary)` |
| `MIN()`   | Finds minimum      | `MIN(salary)` |

**Examples:**

```
-- Count all employees
SELECT COUNT(*) FROM employees;

-- Total salary
SELECT SUM(salary) FROM employees;

-- Average salary
SELECT AVG(salary) FROM employees;

-- Highest salary
SELECT MAX(salary) FROM employees;

-- Lowest salary
SELECT MIN(salary) FROM employees;
```

### **Important COUNT differences**

```
COUNT(*)        -- Counts all rows
COUNT(salary)   -- Counts non-NULL salary values
COUNT(DISTINCT department) -- Counts unique departments
```

Remember: Most aggregate functions ignore `NULL` values. `COUNT(*)` counts rows even when some columns contain NULL.

## **2. Aggregate functions with WHERE**

`WHERE` filters rows before aggregation.

```
-- Calculate salary only for IT employees
SELECT SUM(salary)
FROM employees
WHERE department = 'IT';
```

Result: `165000`

More examples:

```
-- Average salary of IT employees
SELECT AVG(salary)
FROM employees
WHERE department = 'IT';

-- Count employees earning above 45000
SELECT COUNT(*)
FROM employees
WHERE salary > 45000;
```

**Remember:** `WHERE` filters individual rows.

## **3. Aggregate functions with GROUP BY**

`GROUP BY` creates groups based on a column and calculates results separately for each group.

```
SELECT department, SUM(salary)
FROM employees
GROUP BY department;
```

Result:

| department | sum    |
| ---------- | ------ |
| HR         | 85000  |
| IT         | 165000 |

Other examples:

```
-- Count employees in each department
SELECT department, COUNT(*)
FROM employees
GROUP BY department;

-- Average salary per department
SELECT department, AVG(salary)
FROM employees
GROUP BY department;

-- Highest salary in each department
SELECT department, MAX(salary)
FROM employees
GROUP BY department;
```

**Hindi trick:** `GROUP BY` ka matlab hai same values ko ek group mein divide karna, phir har group ka calculation karna.

### **GROUP BY multiple columns**

```
SELECT department, city, COUNT(*)
FROM employees
GROUP BY department, city;
```

This creates groups based on each unique department + city combination.

**Important rule:**

When you use `GROUP BY`, every selected column must generally be:

- Included in `GROUP BY`, or
- Used inside an aggregate function.

Incorrect:

```
SELECT department, name, SUM(salary)
FROM employees
GROUP BY department;
```

Why? One department can have multiple employee names. SQL doesn't know which name to display.

## **4. Aggregate functions with HAVING**

`HAVING` filters groups after aggregation.

```
-- Show departments whose total salary is above 100000
SELECT department, SUM(salary)
FROM employees
GROUP BY department
HAVING SUM(salary) > 100000;
```

Result:

| department | sum    |
| ---------- | ------ |
| IT         | 165000 |

Another example:

```
-- Departments having more than 2 employees
SELECT department, COUNT(*)
FROM employees
GROUP BY department
HAVING COUNT(*) > 2;
```

### **WHERE vs HAVING**

| WHERE                                    | HAVING                            |
| ---------------------------------------- | --------------------------------- |
| Filters individual rows                  | Filters groups                    |
| Before GROUP BY                          | After GROUP BY                    |
| Normally doesn't use aggregate functions | Commonly uses aggregate functions |

**Interview question:** Can we use WHERE with SUM()?

No, not directly. Use `HAVING` when filtering based on an aggregate result.

## **5. GROUP BY + WHERE + HAVING + ORDER BY**

You can combine multiple clauses.

```
SELECT department, AVG(salary) AS avg_salary
FROM employees
WHERE salary > 40000
GROUP BY department
HAVING AVG(salary) > 50000
ORDER BY avg_salary DESC;
```

Understand the flow:

1. `FROM` — Get employees table.
2. `WHERE` — Keep employees earning above 40000.
3. `GROUP BY` — Create department groups.
4. `HAVING` — Keep groups with average salary above 50000.
5. `SELECT` — Display department and average salary.
6. `ORDER BY` — Sort average salary from highest to lowest.

Interview important

## **6. Aggregate functions with DISTINCT**

`DISTINCT` removes duplicate values before the aggregate calculation.

```
-- Count unique departments
SELECT COUNT(DISTINCT department)
FROM employees;
```

```
-- Sum only unique salary values
SELECT SUM(DISTINCT salary)
FROM employees;
```

Difference:

```
SELECT SUM(salary) FROM employees;
SELECT SUM(DISTINCT salary) FROM employees;
```

The first adds every employee's salary. The second adds each different salary value only once.

## **7. Aggregate functions with CASE**

`CASE` lets you perform conditional aggregation.

Example: Count employees based on salary.

```
SELECT
    COUNT(CASE WHEN salary >= 50000 THEN 1 END) AS high_salary,
    COUNT(CASE WHEN salary < 50000 THEN 1 END) AS low_salary
FROM employees;
```

Result:

| high_salary | low_salary |
| ----------- | ---------- |
| 3           | 2          |

Another example: Conditional SUM.

```
SELECT
    SUM(CASE
        WHEN department = 'IT' THEN salary
        ELSE 0
    END) AS it_salary
FROM employees;
```

**Pro tip:** PostgreSQL also provides `FILTER` for conditional aggregation.

```
SELECT
    COUNT(*) FILTER (WHERE salary >= 50000) AS high_salary,
    COUNT(*) FILTER (WHERE salary < 50000) AS low_salary
FROM employees;
```

## **8. Aggregate functions with JOIN**

You can calculate aggregates using multiple tables.

Suppose you have:

**departments**

| id | department_name |
| -- | --------------- |
| 1  | IT              |
| 2  | HR              |

**employees**

| id | name  | department_id | salary |
| -- | ----- | ------------- | ------ |
| 1  | Amit  | 1             | 50000  |
| 2  | Priya | 2             | 40000  |
| 3  | Rahul | 1             | 60000  |

Query:

```
SELECT
    d.department_name,
    COUNT(e.id) AS total_employees,
    SUM(e.salary) AS total_salary
FROM departments d
LEFT JOIN employees e
ON d.id = e.department_id
GROUP BY d.department_name;
```

This gives employee count and total salary for each department.

**Important:** With `LEFT JOIN`, use `COUNT(e.id)` rather than `COUNT(*)` when counting matched employees. `COUNT(*)` also counts the department row when there is no matching employee.

## **9. Advanced: Aggregate functions with subqueries**

Find employees earning more than the company's average salary.

```
SELECT name, salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);
```

How it works:

1. Inner query calculates average salary.
2. Outer query finds employees whose salary is greater than that average.

Advanced example: Departments earning more than the company's average department salary.

```
SELECT department, SUM(salary) AS total_salary
FROM employees
GROUP BY department
HAVING SUM(salary) > (
    SELECT AVG(dept_total)
    FROM (
        SELECT SUM(salary) AS dept_total
        FROM employees
        GROUP BY department
    ) AS department_totals
);
```

## **10. Advanced: Window functions vs aggregate functions**

Aggregate functions normally combine rows into fewer rows.

```
SELECT department, AVG(salary)
FROM employees
GROUP BY department;
```

Window functions calculate results while keeping individual rows.

```
SELECT
    name,
    department,
    salary,
    AVG(salary) OVER (PARTITION BY department) AS dept_avg
FROM employees;
```

Example output:

| name  | department | salary | dept_avg |
| ----- | ---------- | ------ | -------- |
| Amit  | IT         | 50000  | 55000    |
| Rahul | IT         | 60000  | 55000    |
| Priya | HR         | 40000  | 42500    |
| Neha  | HR         | 45000  | 42500    |

**Difference:**

| GROUP BY                  | Window function       |
| ------------------------- | --------------------- |
| Combines rows into groups | Keeps individual rows |
| One result per group      | Result on every row   |
| Uses `GROUP BY`           | Uses `OVER()`         |

## **11. Common mistakes and interview rules**

| Mistake                             | Correct approach                         |
| ----------------------------------- | ---------------------------------------- |
| `WHERE SUM(salary) > 50000`         | Use `HAVING`                             |
| Selecting a non-grouped column      | Add it to `GROUP BY` or aggregate it     |
| `COUNT(salary)` to count all rows   | Use `COUNT(*)`                           |
| Forgetting NULL behavior            | Remember most aggregates ignore NULL     |
| Using `COUNT(*)` after LEFT JOIN    | Use `COUNT(child.id)` to count matches   |
| Assuming `AVG()` returns an integer | PostgreSQL can return a decimal result   |
| Using `SUM()` on text               | Convert to a suitable numeric type first |

### **Bonus aggregate functions in PostgreSQL**

| Function       | Purpose                            |
| -------------- | ---------------------------------- |
| `STRING_AGG()` | Combines text values               |
| `ARRAY_AGG()`  | Collects values into an array      |
| `JSON_AGG()`   | Collects values into JSON          |
| `JSONB_AGG()`  | Collects values into JSONB         |
| `BOOL_AND()`   | True if all values are true        |
| `BOOL_OR()`    | True if at least one value is true |

Example:

```
SELECT STRING_AGG(name, ', ')
FROM employees;
```

Possible output:

`Amit, Priya, Rahul, Neha, Raj`
