# **SQL ALTER — Beginner to Pro (PostgreSQL)**

`ALTER` is used to **change the structure of an existing database object**, such as a table, column, constraint, or index.

Simple Hindi: Table already bana hua hai, usme changes karne ke liye `ALTER` use karte hain.

**Remember:**

- `CREATE` → Create new table.
- `ALTER` → Change existing table structure.
- `DROP` → Remove database object.
- `UPDATE` → Change existing row data.

Let's use this table for examples.

```
CREATE TABLE employees (
    id INT,
    name VARCHAR(50),
    salary NUMERIC(10,2)
);
```

## **1. ALTER TABLE — Add a new column**

Syntax:

```
ALTER TABLE table_name
ADD COLUMN column_name datatype;
```

Example:

```
ALTER TABLE employees
ADD COLUMN email VARCHAR(100);
```

Now employees has a new `email` column.

Add multiple columns:

```
ALTER TABLE employees
ADD COLUMN age INT,
ADD COLUMN department VARCHAR(50),
ADD COLUMN joining_date DATE;
```

**Trick:** `ADD COLUMN` means adding a new column, not adding a new row.

## **2. Change column datatype — ALTER COLUMN TYPE**

Suppose salary is currently `INT`, and you want decimal values.

```
ALTER TABLE employees
ALTER COLUMN salary TYPE NUMERIC(10,2);
```

Change `name` from VARCHAR(50) to VARCHAR(100):

```
ALTER TABLE employees
ALTER COLUMN name TYPE VARCHAR(100);
```

Using `USING` to convert existing data:

```
ALTER TABLE employees
ALTER COLUMN salary TYPE INTEGER
USING salary::INTEGER;
```

`USING` tells PostgreSQL how to convert existing values.

**Important:** Conversion can fail if existing data cannot fit the new datatype. For example, converting `'hello'` to INTEGER fails.

## **3. Rename a column**

Syntax:

```
ALTER TABLE table_name
RENAME COLUMN old_name TO new_name;
```

Example:

```
ALTER TABLE employees
RENAME COLUMN name TO full_name;
```

Now the column is `full_name`, not `name`.

## **4. Rename a table**

```
ALTER TABLE employees
RENAME TO staff;
```

Now the table name is `staff`.

## **5. Drop a column**

Remove an existing column:

```
ALTER TABLE employees
DROP COLUMN email;
```

Drop multiple columns:

```
ALTER TABLE employees
DROP COLUMN age,
DROP COLUMN department;
```

Use `IF EXISTS` to avoid an error if the column doesn't exist:

```
ALTER TABLE employees
DROP COLUMN IF EXISTS email;
```



Caution

&#x20;Dropping a column removes its stored data. It is not the same as hiding the column from SELECT.



## **6. Add DEFAULT value**

Suppose every new employee should have a default department.

```
ALTER TABLE employees
ADD COLUMN department VARCHAR(50) DEFAULT 'IT';
```

Or add a default to an existing column:

```
ALTER TABLE employees
ALTER COLUMN salary SET DEFAULT 30000;
```

Now if you insert an employee without specifying salary, PostgreSQL uses 30000.

```
INSERT INTO employees (id, full_name)
VALUES (1, 'Amit');
```

**Important:** DEFAULT applies when a column is omitted or `DEFAULT` is specified. It does not replace an explicitly supplied `NULL`.

## **7. Remove DEFAULT value**

```
ALTER TABLE employees
ALTER COLUMN salary DROP DEFAULT;
```

This removes the default rule. It does not change existing salary values.

## **8. Add NOT NULL constraint**

Make a column mandatory:

```
ALTER TABLE employees
ALTER COLUMN full_name SET NOT NULL;
```

Now NULL values are not allowed.

Remove NOT NULL:

```
ALTER TABLE employees
ALTER COLUMN full_name DROP NOT NULL;
```

**Interview trick:** If the column already contains NULL values, `SET NOT NULL` will fail. First find and fix them:

```
SELECT *
FROM employees
WHERE full_name IS NULL;
```

## **9. Add constraints using ALTER**

Constraints are rules applied to columns or tables.

### **A. UNIQUE**

```
ALTER TABLE employees
ADD CONSTRAINT unique_email UNIQUE(email);
```

Prevents duplicate non-NULL email values. PostgreSQL allows multiple NULL values by default.

### **B. PRIMARY KEY**

```
ALTER TABLE employees
ADD CONSTRAINT employees_pkey PRIMARY KEY(id);
```

Primary key = UNIQUE + NOT NULL.

It fails if existing IDs are duplicated or NULL.

### **C. FOREIGN KEY**

Suppose we have a departments table:

```
CREATE TABLE departments (
    id INT PRIMARY KEY,
    department_name VARCHAR(50)
);
```

Add a foreign key:

```
ALTER TABLE employees
ADD COLUMN department_id INT;

ALTER TABLE employees
ADD CONSTRAINT fk_department
FOREIGN KEY(department_id)
REFERENCES departments(id);
```

Now `department_id` must match an existing department ID, or be NULL.

### **D. CHECK**

```
ALTER TABLE employees
ADD CONSTRAINT check_salary
CHECK(salary > 0);
```

Salary must be greater than zero. Remember, CHECK alone permits NULL.

### **E. DEFAULT constraint**

```
ALTER TABLE employees
ALTER COLUMN department_id SET DEFAULT 1;
```

In PostgreSQL, a default is a column property, not a separately named constraint.

## **10. Remove constraints**

Use `DROP CONSTRAINT`.

```
-- Remove UNIQUE
ALTER TABLE employees
DROP CONSTRAINT unique_email;

-- Remove PRIMARY KEY
ALTER TABLE employees
DROP CONSTRAINT employees_pkey;

-- Remove FOREIGN KEY
ALTER TABLE employees
DROP CONSTRAINT fk_department;

-- Remove CHECK
ALTER TABLE employees
DROP CONSTRAINT check_salary;
```

Use `IF EXISTS`:

```
ALTER TABLE employees
DROP CONSTRAINT IF EXISTS check_salary;
```

**Trick:** `DROP COLUMN` removes a column. `DROP CONSTRAINT` removes a rule.

## **11. Add multiple changes in one ALTER**

You can perform multiple alterations in one statement:

```
ALTER TABLE employees
ADD COLUMN city VARCHAR(50),
ADD COLUMN age INT,
ALTER COLUMN salary SET DEFAULT 25000;
```

You can also combine constraint operations:

```
ALTER TABLE employees
ADD CONSTRAINT check_age CHECK(age >= 18),
ADD CONSTRAINT unique_name UNIQUE(full_name);
```

This is useful when making related schema changes together.

## **12. Advanced: ALTER TABLE with CASCADE**

Sometimes another object depends on a column or constraint.

Example:

```
ALTER TABLE employees
DROP COLUMN department_id CASCADE;
```

`CASCADE` also removes dependent objects.

Without CASCADE, PostgreSQL may refuse to drop an object that other objects depend on.

**Warning:** Use CASCADE carefully because it can remove more than you intended.

## **13. Advanced: Change column position?**

In PostgreSQL, there is no direct `ALTER TABLE ... MOVE COLUMN` command to change a column's position.

You can control display order using:

```
SELECT id, full_name, salary
FROM employees;
```

This changes the output order, not the actual table structure.

## **14. Advanced: ALTER TABLE and indexes**

Indexes improve searching performance.

Create an index:

```
CREATE INDEX idx_employee_name
ON employees(full_name);
```

Rename an index:

```
ALTER INDEX idx_employee_name
RENAME TO idx_staff_name;
```

Change index name or remove it:

```
DROP INDEX idx_staff_name;
```

Note: `DROP INDEX` is a separate command, not an ALTER TABLE operation.

## **15. ALTER vs UPDATE vs DELETE vs DROP**

| Command  | Purpose                    | Example              |
| -------- | -------------------------- | -------------------- |
| ALTER    | Change table structure     | Add column           |
| UPDATE   | Change existing row values | Change salary        |
| DELETE   | Remove rows                | Delete employee      |
| DROP     | Remove table/object        | Drop employees table |
| TRUNCATE | Remove all rows            | Empty table          |

Example:

```
-- Structure change
ALTER TABLE employees ADD COLUMN age INT;

-- Data change
UPDATE employees SET salary = 50000 WHERE id = 1;

-- Remove selected rows
DELETE FROM employees WHERE id = 1;

-- Remove entire table
DROP TABLE employees;
```

## **16. Practical steps before using ALTER**

Follow this order when modifying an existing table:

1. **Check the table structure**
   ```
   SELECT column_name, data_type
   FROM information_schema.columns
   WHERE table_name = 'employees';
   ```
2. **Check existing data**
   ```
   SELECT * FROM employees;
   ```
3. **Check whether existing values violate your new rule**

   Example: Before adding NOT NULL, find NULL values.
4. **Run ALTER TABLE**

   Add, rename, modify, or remove the required structure.
5. **Verify the changes**
   ```
   SELECT * FROM employees;
   ```

## **17. Common interview mistakes and tricks**

| Situation             | Remember                |
| --------------------- | ----------------------- |
| Add a column          | `ADD COLUMN`            |
| Rename a column       | `RENAME COLUMN`         |
| Change datatype       | `ALTER COLUMN ... TYPE` |
| Remove a column       | `DROP COLUMN`           |
| Set default           | `SET DEFAULT`           |
| Remove default        | `DROP DEFAULT`          |
| Make column mandatory | `SET NOT NULL`          |
| Allow NULL            | `DROP NOT NULL`         |
| Add constraint        | `ADD CONSTRAINT`        |
| Remove constraint     | `DROP CONSTRAINT`       |
| Rename table          | `RENAME TO`             |

**5 important interview questions:**

1. Does ALTER TABLE change existing row values? Usually no, it changes the structure or rules, though some alterations can rewrite or affect stored data.
2. Can we add a PRIMARY KEY to an existing table? Yes, if existing values are unique and non-NULL.
3. Can we change a column datatype? Yes, using `ALTER COLUMN ... TYPE`.
4. What happens when we DROP a column? Its stored data is removed.
5. Difference between SET DEFAULT and UPDATE? SET DEFAULT changes the rule for future inserts; UPDATE changes existing row values.

Remember this simple rule:

- `ALTER TABLE` → Tells PostgreSQL which table you want to change.
- `ALTER COLUMN` → Tells PostgreSQL which column inside that table you want to change.

## **1. Why do we write ALTER twice?**

Example:

```
ALTER TABLE students
ALTER COLUMN age DROP DEFAULT;
```

Explanation:

| Part                   | Meaning                   |
| ---------------------- | ------------------------- |
| `ALTER TABLE students` | Change the students table |
| `ALTER COLUMN age`     | Select the age column     |
| `DROP DEFAULT`         | Remove its default value  |

You are not running ALTER twice. Both are parts of **one ALTER TABLE statement**.

## **2. When to use ALTER COLUMN?**

Whenever you want to modify an existing column.

| Task            | Query                             |
| --------------- | --------------------------------- |
| Change datatype | `ALTER COLUMN age TYPE SMALLINT`  |
| Remove default  | `ALTER COLUMN age DROP DEFAULT`   |
| Set default     | `ALTER COLUMN age SET DEFAULT 18` |
| Make NOT NULL   | `ALTER COLUMN age SET NOT NULL`   |
| Allow NULL      | `ALTER COLUMN age DROP NOT NULL`  |

### **Examples**

**A. Change age datatype**

```
ALTER TABLE students
ALTER COLUMN age TYPE SMALLINT;
```

**B. Remove default**

```
ALTER TABLE students
ALTER COLUMN age DROP DEFAULT;
```

**C. Set default**

```
ALTER TABLE students
ALTER COLUMN age SET DEFAULT 18;
```

**D. Make age mandatory**

```
ALTER TABLE students
ALTER COLUMN age SET NOT NULL;
```

## **3. Can we use multiple ALTER COLUMN in one query?**

Yes!

```
ALTER TABLE students
ALTER COLUMN age TYPE SMALLINT,
ALTER COLUMN age DROP DEFAULT,
ALTER COLUMN age SET NOT NULL;
```

This changes the datatype, removes the default and makes age mandatory in one statement.

Note: This will fail if existing rows contain NULL ages.

## **4. Important difference: DROP DEFAULT vs DROP COLUMN**

```
-- Remove only the default rule
ALTER TABLE students
ALTER COLUMN age DROP DEFAULT;
```

```
-- Remove the entire age column and its data
ALTER TABLE students
DROP COLUMN age;
```

Interview trick

**Remember this structure:**

```
ALTER TABLE table_name
ALTER COLUMN column_name action;
```

Hindi: Pehle table select karo → phir column select karo → phir us column par kya change karna hai woh likho.

One more thing: `SMALLINT` is the datatype, so write it after `TYPE`:

```
ALTER TABLE students
ALTER COLUMN age TYPE SMALLINT;
```

Don't write `DROP DEFAULT SMALLINT` because these are two different operations.

### **1. Rename a column**

```
ALTER TABLE students
RENAME COLUMN age TO student_age;
```

Here:

- `ALTER TABLE students` → Select the table.
- `RENAME COLUMN age` → Select the existing column to rename.

### **2. Modify a column**

```
ALTER TABLE students
ALTER COLUMN age TYPE SMALLINT;
```

Here:

- `ALTER TABLE students` → Select the table.
- `ALTER COLUMN age` → Select the column.
- `TYPE SMALLINT` → Change its datatype.

### **3. Why is the syntax different?**

PostgreSQL has two different commands inside `ALTER TABLE`:

| Action          | Syntax                                |
| --------------- | ------------------------------------- |
| Rename column   | `RENAME COLUMN old TO new`            |
| Change datatype | `ALTER COLUMN name TYPE datatype`     |
| Set default     | `ALTER COLUMN name SET DEFAULT value` |
| Drop default    | `ALTER COLUMN name DROP DEFAULT`      |

**Remember this trick:**

- Rename → `RENAME COLUMN`
- Modify → `ALTER COLUMN`

You don't write `ALTER COLUMN` for renaming because PostgreSQL provides a separate `RENAME COLUMN` command within `ALTER TABLE`.
